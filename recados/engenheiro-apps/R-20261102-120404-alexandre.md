# Bug — Campo: puxar para baixo em Pedidos não atualiza (trava de 20 s engole o pull manual)

## Contexto
Teste de campo do Alexandre no APK de preview do Macuxi Campo (base `demo`, vendedor, online), 02/11. Na tela Pedidos, puxar a lista para baixo não traz o status novo (ex.: pedido aprovado pelo supervisor no Gestão).

**Passos:** Campo → Pedidos → puxar a lista para baixo.

**Esperado:** o app busca no servidor na hora e mostra os status atualizados.

**Obtido:** o indicador aparece, mas nada muda.

**Tela:** Campo → Pedidos (`modules/vendedor/app/screens/orders-screen.tsx`) · **Perfil:** vendedor · **Conexão:** online

## O que preciso / o que mudou
**Causa provável (lida no código):** o `onRefresh` chama `atualizarPedidos` (`app/state/use-vendedor.ts`), que na API v1 só roda `motor.sincronizar()` se passaram mais de `INTERVALO_SYNC_MS` (20 s) desde a última passada. Como o `useFocusEffect` já chama `atualizarPedidos` ao abrir a tela, o puxar para baixo logo depois cai na trava e só relê o aparelho.

1. **Puxar para baixo força a atualização:** ignora a trava de intervalo, envia a fila e faz o pull na hora. Para evitar toque repetido, o puxar só é ignorado se outro manual ocorreu há menos de 30 s, e nesse caso a tela mostra "Atualizado há instantes".
2. Ao terminar: rodapé "Atualizado às hh:mm". Em falha: "Sem conexão com o servidor. Mostrando os dados do aparelho."
3. A atualização automática segue a nova regra geral (3 a 5 min, recado de decisão enviado junto), não a de 20 s.
4. Mesmo comportamento no Gestão (Pedidos da equipe) e nas outras listas com puxar para baixo.

## Pronto quando
- Teste: abrir a tela e puxar logo em seguida dispara um pull real (contagem de chamadas ao `motor.sincronizar`); dois puxões em menos de 30 s fazem só um.
- No APK: o supervisor aprova no Gestão, o vendedor puxa a lista no Campo e vê "Aprovado" na hora.
