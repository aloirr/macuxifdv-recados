# T-0162: revisão do SQL do kit — 5 ajustes médios (A-E) e 3 baixos (F-H) com trecho pronto; status/nota_item no views-modelo; origem só no kit

## Contexto
Revisão estática (sem SQL Server) de modules/integracao/kit-piloto/sql/01, 02 (gerado do entrada-pedido-modelo.sql), 03 e 04, do -Limpar e do caminho do "ERP via API". Resposta ao R-20261112-101245.

**Está certo (ok, sem mudança):**
- tabelas piloto_*: tipos, chaves e S/N;
- views vw_macuxi_* de vendedor, filial, forma, prazo, produto, cliente, preco e estoque: mesmas colunas do views-modelo.sql, external_id texto e sem CNPJ, centavos, data civil e '[]';
- 02: `IF OBJECT_ID ... CREATE TABLE` e `CREATE OR ALTER PROCEDURE`, corpo intacto;
- encadeamento de propriedade: tudo é dbo e criado pelo admin. EXECUTE na procedure grava sem INSERT na tabela; SELECT na view lê sem acesso às piloto_*;
- critério da T-0162 "INSERT na entrada": vale EXECUTE nas 2 procedures + SELECT na entrada (numeroErp), como no modelo;
- macuxi_conector: correto;
- idempotência de 01 a 04 rodando duas vezes;
- -Limpar com DELETE, filhos antes do cabeçalho. O IDENTITY continua, então o numero_erp não se repete no Hub: bom.

**Decisões:**
1. `vw_macuxi_pedido_status` e `vw_macuxi_pedido_nota_item` ENTRARAM no `db/conector/views-modelo.sql` (seções 16 e 17, fora das entidades de carga; teste `db/testes/views-modelo-conector.test.ts` confere as colunas contra o conector.exemplo.json). As colunas são as mesmas do seu 03: nada muda no conector.json.
2. `origem` fica SÓ no kit (03). Não vai ao modelo oficial: ERP real tem um Conector por tenant; duas empresas num ERP só é artefato do piloto. O entrada-pedido-modelo.sql não mudou (o seu `tornarIdempotente` e o teste de 2 tabelas seguem valendo).

## O que preciso (trechos prontos; A a E seguram, F a H são baixos)

**A (média) 03 — status sem nota/motivo é recusado pelo Hub (RetornoErp: faturado exige nota; rejeitado exige motivo).** Hoje, se o dono marcar F/P antes de digitar a nota, o Conector manda faturado sem nota (422, retorno perdido); R sem motivo idem. O "ERP via API" já espera a nota; o Conector precisa da mesma guarda na view. Troque a vw_macuxi_pedido_status por:
```sql
CREATE OR ALTER VIEW dbo.vw_macuxi_pedido_status AS
SELECT p.pedido_uuid,
       CASE WHEN p.situacao IN ('P', 'F') AND p.nota_numero IS NULL THEN 'I' ELSE UPPER(p.situacao) END AS situacao, -- faturado só com nota; 'f' digitado vira 'F'
       p.numero_pedido,
       CASE WHEN p.situacao = 'R' THEN COALESCE(NULLIF(LTRIM(RTRIM(p.motivo)), ''), 'Rejeitado na ERP_PILOTO.') ELSE p.motivo END AS motivo,
       p.nota_numero, p.nota_serie, p.nota_emitida_em, p.nota_total_cents, p.situacao_em AS ocorrido_em
FROM dbo.macuxi_pedido_entrada p;
GO
```

**B (média) 03 — situacao_em não muda sozinha.** O dono faz `UPDATE ... SET situacao = 'F'` no SSMS e o ocorrido_em do Conector fica com a hora do recebimento. Acrescente depois das colunas (antes das views):
```sql
CREATE OR ALTER TRIGGER dbo.tr_pedido_entrada_situacao ON dbo.macuxi_pedido_entrada AFTER UPDATE AS
BEGIN
    SET NOCOUNT ON;
    IF NOT (UPDATE(situacao) OR UPDATE(nota_numero)) RETURN;
    UPDATE p SET situacao_em = SYSUTCDATETIME(),
                 nota_emitida_em = CASE WHEN i.nota_numero IS NOT NULL AND i.nota_emitida_em IS NULL THEN SYSUTCDATETIME() ELSE i.nota_emitida_em END
      FROM dbo.macuxi_pedido_entrada p
      JOIN inserted i ON i.pedido_uuid = p.pedido_uuid
      JOIN deleted d ON d.pedido_uuid = i.pedido_uuid
     WHERE i.situacao <> d.situacao OR ISNULL(i.nota_numero, '') <> ISNULL(d.nota_numero, '');
END;
GO
```
(RECURSIVE_TRIGGERS fica OFF por padrão: o UPDATE interno não dispara de novo. O trigger é dbo: não pede permissão a mais ao macuxi_api.)

**C (média) 03 — nota_item sem chave: linha repetida soma em dobro.** O Conector SOMA as linhas da mesma sequência na nota (pedidos.ts, itensDaNota). Um INSERT repetido no SSMS fatura em dobro. Como o kit ainda não foi publicado, ponha a chave no próprio CREATE:
```sql
IF OBJECT_ID('dbo.macuxi_pedido_nota_item', 'U') IS NULL
CREATE TABLE dbo.macuxi_pedido_nota_item (
    pedido_uuid UNIQUEIDENTIFIER NOT NULL REFERENCES dbo.macuxi_pedido_entrada (pedido_uuid), nota_numero VARCHAR(40) NOT NULL,
    nota_serie VARCHAR(10) NULL, sequencia INT NOT NULL CHECK (sequencia > 0),
    quantidade DECIMAL(14, 3) NOT NULL CHECK (quantidade > 0 AND quantidade = ROUND(quantidade, 0)),
    valor_cents DECIMAL(19, 0) NOT NULL CHECK (valor_cents >= 0), produto_codigo VARCHAR(200) NOT NULL,
    CONSTRAINT pk_macuxi_pedido_nota_item PRIMARY KEY (pedido_uuid, nota_numero, sequencia));
```
O -Limpar já apaga os filhos antes do cabeçalho, então a FK não atrapalha. As regras de quantidade inteira e valor ≥ 0 são as que o Conector exige.

**D (média) 04 — macuxi_api com mais do que usa.** O erp-via-api.mjs grava pelas 2 procedures (encadeamento) e só faz UPDATE de origem e retorno_enviado. INSERT direto na entrada e nos itens sobra, e o vw_piloto_pedidos não é lido por ele. Troque o bloco do macuxi_api por:
```sql
    SET @sql += N'GRANT EXECUTE ON dbo.sp_macuxi_pedido_inserir TO macuxi_api;
GRANT EXECUTE ON dbo.sp_macuxi_pedido_item_inserir TO macuxi_api;
GRANT SELECT ON dbo.macuxi_pedido_entrada TO macuxi_api;
GRANT UPDATE (origem, retorno_enviado) ON dbo.macuxi_pedido_entrada TO macuxi_api;' + CHAR(10);
```
Reinstalação: GRANT não tira o que já foi dado. Ponha antes um `REVOKE INSERT ON dbo.macuxi_pedido_entrada FROM macuxi_api; REVOKE INSERT ON dbo.macuxi_pedido_entrada_item FROM macuxi_api; REVOKE UPDATE ON dbo.macuxi_pedido_entrada FROM macuxi_api; REVOKE SELECT ON dbo.vw_piloto_pedidos FROM macuxi_api;` (REVOKE sem permissão dada não falha).
O cabeçalho do 04 e o teste do kit acompanham: "macuxi_api: o mesmo, mais UPDATE de origem e retorno_enviado".

**E (média) 01 — baixado_em do título cai no dia anterior.** `CAST(t.baixado_em AS DATETIME2(3))` de um DATE vira 00:00 UTC, que é 20h do dia anterior em Boa Vista/Manaus. A data da planilha é civil, no fuso do tenant. Troque por:
```sql
       CAST(CAST(t.baixado_em AS DATETIME2(3)) AT TIME ZONE 'SA Western Standard Time' AT TIME ZONE 'UTC' AS DATETIME2(3)) AS baixado_em
```

**F (baixa) 01 — formas_pagamento do cliente sem DISTINCT nem escape.** 'PIX,PIX' recusa o cliente inteiro: o contrato não aceita código repetido. O modelo usa DISTINCT + STRING_ESCAPE. Troque o CASE por:
```sql
       COALESCE((SELECT '[' + STRING_AGG('"' + STRING_ESCAPE(x.codigo, 'json') + '"', ',') WITHIN GROUP (ORDER BY x.codigo) + ']'
                   FROM (SELECT DISTINCT UPPER(LTRIM(RTRIM(s.value))) AS codigo FROM STRING_SPLIT(c.formas_pagamento, ',') s
                          WHERE LTRIM(RTRIM(s.value)) <> '') x), '[]') AS formas_pagamento
```

**G (baixa) 01 — CHECK de parcelas_dias deixa passar '' e vírgula sobrando.** Viram '[]' e '[30,,60]', que o Hub recusa. Troque o CHECK por:
```sql
    parcelas_dias VARCHAR(120) NOT NULL CHECK (parcelas_dias <> '' AND parcelas_dias NOT LIKE '%[^0-9,]%' AND parcelas_dias NOT LIKE '%,,%' AND parcelas_dias NOT LIKE ',%' AND parcelas_dias NOT LIKE '%,'),
```
(A tabela é criada com guarda: vale para instalação nova, e o kit ainda não saiu.)

**H (baixa) carregador — códigos com caixa diferente entre planilhas.** O SQL Server do kit não diferencia maiúsculas: 'p001' no preço casa com 'P001' no produto. O Hub compara external_id binário e recusa o preço. Sugestão: o Instalar-Piloto.ps1 passa a ToUpperInvariant() nas colunas *codigo* (como já faz com uf).

**Informativo — ROTEIRO, -Limpar:** o DELETE apaga os cadastros de verdade. O Macuxi só inativa o que sumiu na carga COMPLETA (RN-INT-06). Depois de -Limpar + recarga, diga no roteiro para pedir a carga completa no BKO; senão os cadastros antigos ficam ativos no app.
