# T-0162: 6 defeitos no kit do piloto (D-T0162-1 a 6), 7 testes it.fails em tests/modulos/kit-piloto-t0162.test.ts

## Contexto
Validação do kit do piloto (T-0162, R-20261112-113348). Teste: `tests/modulos/kit-piloto-t0162.test.ts`, com 23 casos, 7 deles `it.fails`, um por defeito aberto. Matriz: `docs/testes/T-0162.md`. Cada `it.fails` falha pelo motivo descrito abaixo: conferi rodando os 7 como `it`. Na correção, troque `it.fails` por `it` no mesmo commit (o arquivo é meu, então me avise e eu troco, ou mande a correção que eu viro).

## O que preciso (D-T0162-n)
1. **D-T0162-1 (alta), `erp-via-api/erp-via-api.mjs`, `parametrosDoPedido`.** O código lê `pg.forma.codigo`, `pg.forma.external_id`, `pg.prazo.codigo` e `pg.prazo.external_id`. O contrato `PagamentoErp` (`modules/integracao/contracts/pedido.ts`) e o Conector (`apps/conector/src/pedidos.ts`, `parametrosCabecalho`) usam campos planos: `forma_codigo`, `forma_external_id`, `prazo_codigo` e `prazo_external_id`. Na Piloto API, a forma e o prazo vão NULL para a ERP_PILOTO (RN-VEN-24). A fixture `PEDIDO` do `kit-piloto.test.ts` usa o formato aninhado e esconde o erro: monte-a com `PedidoParaErp.parse`. Observação no mesmo trecho: sem `origem` no endereço, o Conector grava `entrega_origem = 'erp'` e o ERP via API grava NULL. Alinhe ao Conector.
   - Reproduzir: `parametrosDoPedido(PedidoParaErp.parse({... pagamento: { forma_codigo: 'BOLETO', prazo_codigo: 'BOL-3060', parcelas_dias: [30,60], prazo_medio_dias: 45 }}))` devolve `pagamento_forma_codigo: null`.
2. **D-T0162-2 (média), `sql/01-erp-piloto.sql` e `erp-via-api.mjs`.**
   - O CHECK `parcelas_dias NOT LIKE '%[^0-9,]%'` aceita `30,,60`, `30,60,` e `,30`. A `vw_macuxi_prazo_pagamento` vira `[30,,60]`, o `converterLinha` dá `JSON.parse` em SyntaxError e o `executarCiclo` cai antes do `processarPedidos`.
   - Efeito: uma vírgula a mais na planilha para a carga e também os pedidos e retornos da Piloto API, a cada minuto, até alguém corrigir a planilha. O log diz só "Unexpected token".
   - Pronto quando:
     - o CHECK recusa vírgula vazia (a planilha mostra a linha recusada, como hoje);
     - a falha de carga de uma entidade não impede os pedidos e os retornos da mesma passada: a carga fica para a próxima passada e o log diz qual entidade falhou, sem dado de linha.
3. **D-T0162-3 (baixa), `enviarRetornos`.** O `ocorrido_em` usa `agora()`. O 03 diz que o `situacao_em` vira o `ocorrido_em` do status, e o Conector usa `vw_macuxi_pedido_status.ocorrido_em = situacao_em`. Selecione o `situacao_em` e use-o (ISO sem ms, como o resto).
4. **D-T0162-4 (média, segurança), `Instalar-Piloto.ps1`, `Passo-Rede-Sql`.**
   - O `New-NetFirewallRule ... -RemoteAddress LocalSubnet -Profile Any` também vale no perfil Público: num Wi-Fi de hotel ou café, a "rede local" são estranhos. Use `-Profile Private,Domain`.
   - Como a regra já pode existir (a guarda é só pelo nome), atualize-a em quem já instalou: `Set-NetFirewallRule -DisplayName $regra -Profile Private,Domain -RemoteAddress LocalSubnet`.
   - O Conector e o ERP via API usam 127.0.0.1 e não dependem dessa regra.
5. **D-T0162-5 (média), `erp-via-api/executar.ps1`.**
   - Com `$ErrorActionPreference = 'Stop'` e `& $node ... *>> log`, no Windows PowerShell 5.1 a 1ª linha de stderr do node vira NativeCommandError terminante e não vai ao log.
   - Reproduzi neste PC (PS 5.1.26100) com um .mjs que faz `console.log` e `console.error`: o log ficou só com a linha do stdout, o `ERRO: 401 chave_invalida` saiu no console (que na tarefa agendada fica oculto) e a linha seguinte ao node não rodou.
   - Assim, o "API sem andar: veja o erp-via-api.log" do roteiro não mostra o erro. Qualquer aviso do Node em stderr também derruba o wrapper.
   - Pronto quando a chamada do node roda com `$ErrorActionPreference = 'Continue'` (ou por `cmd /c ... >> log 2>&1`) e o `exit $LASTEXITCODE` continua.
6. **D-T0162-6 (média), `Instalar-Piloto.ps1`, idempotência.**
   - O `Passo-Banco` troca as senhas de `macuxi_conector` e `macuxi_api` a cada execução (com `-Modalidade Ambas`, sempre), mas o cofre só é atualizado depois.
   - (a) No `Passo-Api`, `Gravar-Credencial 'Macuxi.Piloto/erp_senha_api'` vem depois do `npm install`. Se o npm falha (sem internet), a Piloto API fica com a senha velha e perde o banco.
   - (b) No `Passo-Conector`, se o `conector-*.zip` não está na pasta, o passo é pulado com um aviso, mas a senha já foi trocada e o serviço já instalado perde o banco.
   - O uso diário ("edite a planilha e rode o instalador de novo") passa por esses dois caminhos.
   - Pronto quando:
     - a senha só é trocada quando a modalidade vai mesmo ser reconfigurada, ou vai ao cofre logo depois da troca (antes de qualquer passo que possa falhar);
     - o npm é pulado quando o `node_modules/mssql` já existe na versão do `package.json`.
