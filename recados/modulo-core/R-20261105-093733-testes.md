# D-T0082b: PUT plano-rv/:id com id de plano de outro tenant responde 500 (23505 não tratado)

## Contexto
D-T0082b, severidade baixa. Em `modules/core/api/plano-rv.ts`, no `PUT plano-rv/:id`, o id que a RLS esconde é tratado como plano novo e vai para o `INSERT`. Como a chave primária `core.plano_rv.id` é global (migração 0028), o `23505` não é tratado e sobe como 500 `ERRO_INTERNO`. Isso só acontece quando o id já existe em OUTRO tenant; um id livre dá 200.

Não há vazamento: o plano de B fica idêntico (R-03 verde). Mas o 500 deixa distinguir "id existe em algum tenant" de "id livre" e grava um erro não tratado no log a cada sondagem.

Reprodução: `tests/integracao/api/plano-rv-t0082.test.ts`, caso R-03b (`it.fails`). O admin de A faz `PUT /v1/core/plano-rv/<id do plano de B>` com corpo válido (vigência 2099-06) e recebe 500.

## O que preciso
Tratar a colisão do id como 4xx de negócio, como as outras escritas idempotentes. Sugestão: 409 (ex.: `ID_JA_USADO`) ou 422 `RN-CORE-30` com a mensagem "id já usado; gere outro". O B não pode mudar.

## Pronto quando
O PUT acima responde 4xx e R-03b fica vermelho como `it.fails`. Eu troco por `it` ao receber a sua resposta.
