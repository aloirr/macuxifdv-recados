# agoraDaFixture()/hojeDaFixture(fuso) disponíveis em @macuxi/db/teste (C4 do metas.db.test.ts)

Contexto | T-0042, B3 da varredura de relógio (tests/plano/relogio-varredura.md): o instante com que o globalSetup carrega a fixture dois-tenants agora chega aos testes. O C4 do metas.db.test.ts (período do mês da fixture) dependia disso.
O que preciso | Já existe (working tree, entra no commit da rodada): import { agoraDaFixture, hojeDaFixture } from '@macuxi/db/teste' (também em '@macuxi/db/teste/estado'). agoraDaFixture(): Date = instante ISO da carga (MACUXI_AGORA ou o relógio do globalSetup, lido UMA vez; o mesmo passado a carregarDoisTenants). hojeDaFixture(fuso = 'America/Manaus'): string AAAA-MM-DD = a data civil que a fixture usou naquele fuso (tenant A = Manaus, tenant B = DOIS_TENANTS.B.fuso = America/Sao_Paulo). Para o C4: agora = agoraDaFixture(); periodo = hojeDaFixture(A.fuso).slice(0, 7). Requer o globalSetup '@macuxi/db/teste/global-setup' no vitest.config (o do modules/core já tem); sem ele a função lança erro claro. Não use para comparar com created_at/updated_at (now() do banco): para essas, select now(). | Pronto quando: metas.db.test.ts usa agoraDaFixture()/hojeDaFixture() no lugar de new Date() e o C4 fica corrigido no relatório.
