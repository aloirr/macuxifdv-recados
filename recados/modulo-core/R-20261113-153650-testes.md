# PR #142 vermelho: 2 testes do core desatualizados (cadastro.test.ts RD-0183 e fixture de metas-produtividade sem os campos da T-0168)

## Contexto
PR #142 (M0 v1.0.5, `lote/v1.0.5-m0`, head `05f7dfb2`), runs 43479513041 e 43485344140, job "testes dos pacotes": 2 vermelhos em `@macuxi/core`. Os dois são teste desatualizado; o código de produção está certo.

1. `modules/core/domain/cadastro.test.ts:141`, "RN-CORE-17: é refeita a cada atualização, sem acumular linhas antigas".
   Erro: esperado `'Cadastro incompleto: falta CNPJ/CPF. Pedido só como orçamento até o cadastro ser completado no ERP.\nTexto do ERP'`; recebido `'Cadastro incompleto: falta CNPJ/CPF.\nTexto do ERP'`.
   Causa: a RD-0183 (T-0166) tirou a 2ª frase de `observacaoComCadastro` (`modules/core/domain/cadastro.ts:118`, RN-CORE-17 do doc 03 já diz isso), mas esta expectativa ficou com o texto antigo.

2. `modules/core/web/components/metas-produtividade/metas-produtividade.test.ts:179` (só no PR, T-0170), "Empresa, Equipe e Usuário (só vendedor e promotor na lista); o mês começa no de hoje".
   Erro: o HTML não tem `data-testid="metas-prod.escopo.usuario"`, só `.tenant` e `.equipe`.
   Causa: cruzamento T-0170 × T-0168. O fixture `usuario` do teste não tem os 3 campos obrigatórios do `LimiteDescontoSchema` (`desconto_limita_item`, `desconto_limita_pedido`, `desconto_maximo_pedido_permil`), que a T-0168 espalhou no `UsuarioItemSchema` (strict). Com isso, `UsuarioListaRespostaSchema.parse` falha em `api.consultores`, a query dá erro e a opção "Usuário" some (o `ESCOPOS.filter` depende de `consultores.data`). A API real manda os campos, então a produção está certa.

   `expect(v2).toBe('Cadastro incompleto: falta CNPJ/CPF.\nTexto do ERP');`
