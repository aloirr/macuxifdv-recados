# D-5: cargas da Fase M do Core engolem 401 e 423 (ou4xxNulo trata todo 4xx como vazio)

## Contexto
modules/core/app/lib/cargas.ts: ou4xxNulo usa erroDeCliente (http.ts, status 400..499) nas etapas 'metas' (/goals/me) e 'pedidos-da-visita' (/orders). Com a sessão vencida (401 NAO_AUTENTICADO) ou o aparelho bloqueado (423 DISPOSITIVO_BLOQUEADO, RN-CORE-15) o 'Sincronizar' termina com sucesso e a tela diz 'Pronto'. O Vendedor já corrigiu o mesmo caso (D-4, modules/vendedor/app/etapas.ts rotaInexistente: só 404/501/SYNC_NAO_IMPLEMENTADO viram pulo). Reproduz: tests/integracao/api/visitas-campo.test.ts S1-043d (aparelho com etapas: etapasCore e o HTTP das etapas respondendo 401 → sincronizar() = true; esperado false com o código no erro).

## O que preciso / o que mudou
Que as cargas do Core tolerem só 'não existe/vazio' (404, 501/SYNC_NAO_IMPLEMENTADO e, se for intencional para /orders sem Vendedor, 403 MODULO_INATIVO) e deixem 401, 423 (e 403 PERFIL_SEM_ACESSO, se não for intencional) derrubarem a sincronização. Unitário no cargas.test.ts.

## Pronto quando
Pronto quando o S1-043d ficar vermelho como it.fails (eu troco por it) e me avisar por recado.
