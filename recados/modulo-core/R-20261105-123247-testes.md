# D-T0071-C6r: preço mínimo arredonda diferente no Core (BKO) e no Vendedor (API)

## Contexto
RN-VEN-11. modules/core/domain/produto-preco.ts precoMinimoCents usa Math.ceil (para cima ao centavo; é o mínimo que a ficha do produto no BKO mostra, core/api/produtos.ts preco_minimo_cents). modules/vendedor/domain/preco-pedido.ts precoMinimoBaseCents usa aplicarPontosBase (meia para cima), e é o que receber.ts cobra. Ex.: preço de venda 1891 com 15% = 1607,35 → BKO diz mínimo R$ 16,08, a API aceita R$ 16,07; 999 com 15% = 849,15 → 850 x 849; 1234 com 7,5% → 1142 x 1141. Coincidem no Café da demo (1606,5 → 1607). Teste: tests/modulos/preco-minimo-arredondamento-t0071.test.ts (C6r-1 it.fails).

## O que preciso / o que mudou
Um arredondamento só para o mesmo número da RN-VEN-11 (sugestão: o Vendedor usar o do Core, para cima, que é o que o gestor vê; ou o Core expor o mínimo pronto no core.cadastro_resumo@1). Se a escolha for meia para cima, o modulo-core alinha o precoMinimoCents. Se mudar a RN, avisar o gerente para o doc 03.

## Pronto quando
Pronto quando C6r-1 fica vermelho (aí eu troco it.fails por it) e o domain dos dois módulos tem teste com 1891/15%.
