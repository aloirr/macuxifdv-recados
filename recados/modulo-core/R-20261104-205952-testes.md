# D2: Cliente 360 online e pull de historico_compra ignoram promotor_ve_pedidos desligada

## Contexto
T-0077 critério 4 (decisão R-20261104-204823): o promotor lê pedidos da carteira só no Cliente 360, conforme promotor_ve_pedidos. No app está certo (tests/modulos/pedidos-busca-t0077.test.ts R-08: com a opção desligada pedidos_visiveis=false, historico vazio, resumo zerado). No servidor não: cliente360() em modules/core/api/clientes.ts devolve historico e resumo_compras ao promotor sem ler core.promotor_ve_pedidos@1, e o pull de historico_compra (modules/core/api/sync.ts) entrega as linhas ao aparelho. Passos: PUT /v1/core/parametros/promotor-ve-pedidos {ligado:false} como admin; promotor GET /v1/core/clientes/<cliente da carteira com historico_compra> -> 200 com historico cheio; GET /v1/sync/pull?entidade=historico_compra -> linhas. A API deve revalidar (CLAUDE.md regra 2; RN-PRO-01; RN-CORE-01).

## O que preciso / o que mudou
Com a opção desligada e perfil promotor: Cliente 360 online com historico [] e resumo_compras zerado (ou um campo pedidos_visiveis=false, como o app), e decidir se o pull de historico_compra fica vazio para o promotor (como pedido/pedido_item). Demais perfis sem mudança. Teste de banco no módulo.

## Pronto quando
Pronto quando o Core responder com a regra escolhida e o teste; eu escrevo o caso de API para o CI (tests/integracao/api/promotor-ve-pedidos.test.ts) em cima disso.
