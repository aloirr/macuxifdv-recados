# Pré-cadastro de cliente: o vendedor faz no app, vai direto ao ERP e quem aprova é o ERP

Texto literal do Alexandre (chat com o Agente PO, 23/11/2026 10h27 de Manaus), depois de saber que a v1.0.27 entregou só a API do cliente novo, sem as telas do Campo e do BKO:

> O FDV só faz pre cadastro mesmo. o Vendedor faz, chega no ERP e o BKO aprova por lá.

## O que fica decidido
1. Fluxo do cliente novo (RF-CORE-10): o vendedor faz o **pré-cadastro no app Campo**; o pré-cadastro vai **direto ao ERP** pela API (sem aprovação no BKO do FDV); a aprovação acontece **no ERP**, que devolve o código do cliente (ou a recusa) pelo retorno da API.
2. Não há tela de aprovação de cliente no BKO do FDV. A regra "aprovado no BKO" da v1.0.27 (RN-CORE-78 / RN-INT-22) muda: o pré-cadastro fica disponível para o ERP assim que o vendedor grava (e sincroniza).
3. v1.0.28: tela de pré-cadastro no app Campo (se não existir), ajuste da regra e da API, e o cliente aparece com a tag "Pré-Cadastro" até o ERP devolver o código. Exige APK novo, que leva junto a borda #7A8593.
4. O gerente confirma se a tela do Campo já existe e manda a previsão; deploy só com "aprovo deploy v1.0.28".
