# Bug de segurança — teste do servidor aceita qualquer site e o login envia as credenciais para ele

## Contexto
Teste de campo do Alexandre no APK de preview do Macuxi Campo (T-0026), com vídeo e prints. Explica a falha relatada em R-20261101-023528-alexandre.

**Passos**
1. Tela Entrar → Servidor → Alterar.
2. Digitar o endereço com um erro de digitação: `https://vampire-populations-tractor-fabric.trycloudfare.com` (falta o "l" de trycloudflare).
3. Tocar em "Testar e salvar" → o app mostra **"Servidor respondeu."** e salva `https://…trycloudfare.com/v1`.
4. Preencher código `demo`, e-mail `vendedor@exemplo.com.br` e senha → Entrar.

**Esperado:** no passo 3, "Este endereço não é um servidor Macuxi" e nada salvo. O login nunca sai do aparelho para um servidor que não seja do Macuxi.

**Obtido:** o teste aceitou um domínio que não é nosso (provavelmente um site de terceiro que responde a qualquer caminho). O login enviou código, e-mail e senha para ele e mostrou o erro genérico "Não foi possível entrar agora. Tente de novo; se continuar, avise o suporte."

**Tela:** Entrar, cartão Servidor (`server-input`) e `login.erro` · **Perfil:** vendedor (antes do login) · **Conexão:** online

## O que preciso / o que mudou
**Segurança: credenciais enviadas a um servidor que não é nosso.**
1. `GET /v1/saude` (`apps/api/src/app.ts`) devolve uma identificação verificável, ex.: `{ ok: true, servico: "macuxi-api", versao }`. O app (`testApiUrl` em `apps/mobile/src/state/plataforma.tsx` e `ApiClient.health`) valida o corpo com Zod: status 200, JSON e `servico === "macuxi-api"`. Qualquer outra coisa conta como falha: "Este endereço não é um servidor Macuxi".
2. O login só é enviado para um servidor que passou nessa validação. Fora do desenvolvimento, só aceitar `https://`.
3. Mensagem de login (modulo-core, `mensagemDeErroDeLogin` em `modules/core/app/lib/login.ts`): separar "sem conexão / servidor não respondeu", "resposta inválida do servidor" e "código, e-mail ou senha incorretos", cada uma com a ação seguinte. O erro genérico fica só para o imprevisto.

## Pronto quando
- Com um domínio errado que responde HTML ou JSON qualquer, "Testar e salvar" falha com a mensagem acima e não salva.
- Com o túnel correto da demonstração, o teste passa e o login entra.
- Testes: unitário da validação de saúde (JSON certo, HTML, JSON sem `servico`, 404, timeout) e da escolha da mensagem de login.
- Recado de entrega dos dois agentes (engenheiro-software: saúde e cartão; modulo-core: mensagens).
