# D-MP1: login decide o app só pelo perfil principal (multiperfil e sobreposições da 0041 ignorados)

## Contexto
Mesmo ponto do 🟡 1 da revisão R-20261108-061203-engenheiro-software, agora com teste de ponta. modules/core/api/autenticacao.ts:201 usa podeUsarApp(perfisDeFabrica(u.perfil), e.app). Com os perfis da 0041 (plataforma.perfis_do_usuario) a regra é a da ADR 0033 §7 / RN-CORE-35 (acessos pela mais restritiva, apps somam, sobreposição de acesso.* vale). Hoje: analista + vendedor entra no BKO (web) e é recusado no Campo; admin + vendedor entra no BKO; o perfil vendedor_balcao de B (acesso.campo revogado) entra no Campo. As rotas 'bko' já recusam (a API lê os perfis), mas o login abre sessão. Fica alcançável assim que a rota de usuário gravar usuario_perfil (usuarios.ts já audita 'perfis' no criar) — então precisa entrar antes ou junto. A mensagem de PERFIL_FORA_DO_APP deve seguir o perfil que fechou o app.

## O que preciso / o que mudou
Ler os perfis do usuário no login (perfis_do_usuario na transação do tenant) e decidir com resolverPerfil + podeEntrar/podeUsarApp do SDK; o mesmo na troca de senha com app.
