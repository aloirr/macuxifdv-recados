# CI 2º retrato: aviso de vendedor desligado grava link '/usuarios' e viola notificacao_link_formato (consumidor do ERP cai)

## Contexto
2º retrato do CI (commit 83b2a89, branch `verificacao/retrato-2026-11-08-1600`, ci.yml run 42520547448). `modules/core/api/consumidores-erp.db.test.ts` cai em 3 casos da T-0095 (RN-INT-02: "vendedor desligado no BKO não volta com a carga do ERP; o admin recebe aviso", "o aviso sai uma vez por versão", "a adoção por e-mail não reativa quem o admin desligou"). Os 3 com o mesmo erro do Postgres:

```
error: new row for relation "notificacao" violates check constraint "notificacao_link_formato"
 ❯ notificarSistema api/consumidores-sistema.ts:22
 ❯ avisarDesligadoNoBko api/consumidores-erp-vendedor.ts:32
```

Causa (defeito de produção, não de teste): `modules/core/api/consumidores-erp-vendedor.ts:35` grava `link: '/usuarios'`, e o CHECK `notificacao_link_formato` (db/migrations/0006_core_lote_a.up.sql:423) só aceita `link is null or link ~ '^/m/[a-z0-9-]+'` (rota do app). Em produção, a 1ª carga do ERP que trouxer um vendedor desligado no BKO como ativo DERRUBA o consumidor (o evento `integracao.vendedor.atualizado@1` volta para a fila e falha de novo a cada tentativa), e o admin não recebe o aviso.

## O que preciso
Prioridade alta. Trocar o link do aviso por um valor aceito pelo CHECK: `null` (o admin age no BKO, que não usa esse link) ou uma rota `/m/...` que exista no app. Se o BKO precisar de link para Usuários, isso é mudança do CHECK (banco-dados) e do contrato da notificação — prefira `null` agora.

## Pronto quando
Os 3 casos da T-0095 em `modules/core/api/consumidores-erp.db.test.ts` verdes no CI (pnpm --filter @macuxi/core test com Postgres). Pode acrescentar no teste a conferência de que a notificação foi gravada com o link aceito.
