# 0035 pronta: tabelas, colunas e assinaturas finais das funções sa_* (o seu repositório já bate)

## Contexto
T-0087 fatia P: a migração `db/migrations/0035_plataforma_super_admin.up.sql` (ADR 0029, desenho docs/desenho/T-0087.md §6) está pronta no local; os testes de banco rodam no CI. Dicionário completo: `docs/banco/plataforma.md`, seção "Super-admin de plataforma". O Core NÃO lê as tabelas direto (RLS forçado sem política e sem grant para o `macuxi_app`: 42501); tudo pelas funções abaixo, chamadas com o `macuxi_app` sem contexto de tenant (`semTenant`).

## Tabelas (só para referência; acesso só por função)
- `plataforma.super_admin`: id, email, nome, senha_hash (argon2id), totp_segredo_cifrado, totp_pendente_cifrado (formato `v1.<iv>.<tag>.<cifra>`, CHECK), totp_confirmado_em, totp_ultimo_passo (bigint), recuperacao_hashes (text[], SHA-256 hex; nunca sai do banco), falhas, bloqueado_ate, ativo + colunas padrão (sem tenant_id).
- `plataforma.super_admin_desafio`: id, super_admin_id, desafio_hash (SHA-256 hex), etapa (`segundo_fator` | `cadastrar_totp`), expira_em (até 5 min), consumido_em.
- `plataforma.super_admin_sessao`: id (= `sid` do token), super_admin_id, criada_em, ultimo_uso_em, expira_em (teto de 8 h), revogada_em.
- `plataforma.auditoria_plataforma` (append-only): id, super_admin_id, sessao_id, tenant_alvo_id, acao, metodo, rota, status, request_id, ip_prefixo, detalhes, ocorrido_em.

## Funções (assinaturas finais)
- `sa_existe() → boolean` (qualquer linha, mesmo apagada: o primeiro acesso responde 410 para sempre).
- `sa_criar_primeiro(p_email text, p_nome text, p_senha_hash text) → uuid | null` (trava consultiva; null = já existe; 22023 na entrada inválida, sem dado pessoal na mensagem).
- `sa_para_login(p_email text)` e `sa_por_id(p_id uuid) → table (id, email, nome, senha_hash, ativo, falhas, bloqueado_ate, totp_confirmado_em, totp_segredo_cifrado, totp_pendente_cifrado, totp_ultimo_passo bigint, recuperacao_restantes integer)`. 0 linhas = não existe. Atenção: o bigint chega como TEXTO no node-pg (use Number()).
- `sa_registrar_falha(p_id uuid) → table (falhas integer, bloqueado_ate timestamptz)`: a 5ª falha seguida põe bloqueado_ate = now()+15 min e zera falhas; se já bloqueado, nada muda e devolve o estado. `bloqueado_ate > now()` → 423.
- `sa_registrar_sucesso(p_id uuid) → void` (não desfaz bloqueio vigente).
- `sa_gravar_totp_pendente(p_id uuid, p_cifrado text) → boolean` (só antes do TOTP confirmado).
- `sa_confirmar_totp(p_id uuid, p_passo bigint, p_recuperacao_hashes text[]) → boolean`: pendente vira segredo + passo usado + 1 a 20 hashes distintos, numa só chamada (é aqui que entram os 10 códigos de recuperação).
- `sa_marcar_passo(p_id uuid, p_passo bigint) → boolean` (true só se o passo for maior que o último: sem reuso).
- `sa_usar_recuperacao(p_id uuid, p_hash text) → integer | null` (quantos restam; null = não vale).
- `sa_regerar_recuperacao(p_id uuid, p_hashes text[]) → integer | null`.
- `sa_abrir_desafio(p_id uuid, p_desafio_hash text) → table (etapa text, expira_em timestamptz)`: 0 linhas se inativo, apagado ou bloqueado; a etapa é decidida pelo banco (sem TOTP confirmado = `cadastrar_totp`); invalida o desafio anterior ainda aberto.
- `sa_ver_desafio(p_desafio_hash text) → table (super_admin_id uuid, etapa text, expira_em timestamptz)`: não consome (use em totp/iniciar, totp/confirmar e segundo-fator para saber quem é).
- `sa_abrir_sessao(p_desafio_hash text) → table (sessao_id uuid, super_admin_id uuid, expira_em timestamptz)`: CONSOME o desafio e abre a sessão de 8 h só com TOTP confirmado, ativo e sem bloqueio. Chame depois de conferir o código (e de `sa_marcar_passo`/`sa_usar_recuperacao` ou `sa_confirmar_totp`).
- `sa_sessao_valida(p_sid uuid) → table (super_admin_id uuid, expira_em timestamptz)`: 0 linhas = inválida; atualiza ultimo_uso_em. É o "renovar" e a base do `autenticarSuperAdmin` (compare super_admin_id com o `sub` do token). `expira_em` = `sessao_expira_em` do `SessaoPlataformaSchema`.
- `sa_revogar(p_sid uuid) → boolean` (sair).
- `sa_auditar(p jsonb) → uuid`: `{ super_admin_id?, sessao_id?, tenant_id?, acao, metodo?, rota?, status?, request_id?, ip_prefixo?, detalhes? }`; acao `^[a-z][a-z0-9_.]{0,79}$` (senão 22023); detalhes objeto até 4 KB; IP só /24 ou /48 (outro formato vira nulo).

Fluxos: primeiro acesso = `sa_criar_primeiro` → `sa_abrir_desafio` (etapa cadastrar_totp). Login = `sa_para_login` → argon2 → `sa_registrar_sucesso`/`sa_registrar_falha` → `sa_abrir_desafio`. Cadastro do TOTP = `sa_ver_desafio` → `sa_gravar_totp_pendente` → (confirmar) `sa_ver_desafio` + `sa_por_id` → conferir → `sa_confirmar_totp` → `sa_abrir_sessao`. 2ª etapa = `sa_ver_desafio` + `sa_por_id` → conferir → `sa_marcar_passo` (ou `sa_usar_recuperacao`) → `sa_abrir_sessao`; código errado = `sa_registrar_falha`.

O banco já grava na auditoria (detalhes.origem = 'banco'): `sa.primeiro_acesso`, `sa.totp.confirmado`, `sa.bloqueio`, `sa.sessao.aberta`, `sa.sessao.revogada`, `sa.recuperacao.usada`, `sa.recuperacao.regerada`, `sa.tenant.provisionar`. Do Core faltam só os fatos com IP e request_id (login ok/falha, código errado, 410 do primeiro acesso), por `sa_auditar`; não precisa duplicar os do banco.
