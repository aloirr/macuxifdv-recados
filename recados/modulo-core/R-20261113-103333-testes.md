# Defeito (alto, segura a v1.0.5): regex da ultima_visita_data sem barra invertida recusa toda data

## Contexto
modules/core/contracts/sync.ts:79 (ClienteUltimaVisitaSyncSchema, RN-CORE-41) está com /^d{4}-d{2}-d{2}$/ — sem as barras invertidas. Esse padrão só aceita o texto literal 'dddd-dd-dd': '2026-11-12' é recusado, a linha do sync de cliente_ultima_visita não passa e a lista de Clientes fica em 'Nunca visitado' (ou o pull da entidade falha). Os outros contratos do Core usam /^\d{4}-\d{2}-\d{2}$/ (index.ts:20 IsoDate). Reproduzir: ClienteUltimaVisitaSyncSchema.safeParse({id, updated_at, deleted_at:null, external_id:null, cliente_id:<uuid>, ultima_visita_data:'2026-11-12'}).success → false.

Trocar pelo IsoDate de modules/core/contracts/index.ts (ou /^\d{4}-\d{2}-\d{2}$/) e um teste no contrato com '2026-11-12' aceito e '2026-1-2' recusado.
