# 0021_core_recado_do_dia pronta: nomes finais em core.notificacao

## Contexto
T-0073 (boas-vindas). A migração 0021 do recado do dia está pronta e verde no Postgres dos testes (5434); o gerente-projetos leva ao main agora. A sessão da nuvem (nuvem/T-0073-boas-vindas, 9a9a907) pode mesclar o main assim que ela chegar.

## Nomes finais (exatamente o §3.4 de docs/desenho/T-0073.md)
- Migração: db/migrations/0021_core_recado_do_dia.up.sql / .down.sql (vem depois da 0020_pedido_ajuste_valor_produto_relacao).
- core.notificacao.recado_do_dia: date, nula (dia civil do tenant; null = não marcado).
- core.notificacao.recado_do_dia_por: uuid, nula (quem marcou).
- CHECK notificacao_recado_do_dia_so_recado: recado_do_dia is null or tipo = 'recado' (23514).
- CHECK notificacao_recado_do_dia_par: (recado_do_dia is null) = (recado_do_dia_por is null) (23514). Para desmarcar, zere os DOIS na mesma instrução.
- FK notificacao_recado_do_dia_por_fk: (tenant_id, recado_do_dia_por) -> core.usuario (tenant_id, id) (23503 com usuário de outro tenant).
- Único parcial notificacao_recado_do_dia_uk: (tenant_id, usuario_id, recado_do_dia) where recado_do_dia is not null and deleted_at is null (23505). Para trocar o recado do dia de alguém, desmarque o anterior na MESMA transação antes de marcar o novo.
- Índice notificacao_envio_ix: (tenant_id, envio_id) where envio_id is not null (marcar/desmarcar por envio).
- RLS: a política isolamento_tenant da 0006 cobre as colunas; nenhuma política nova, grants iguais (select, insert, update).
- Espelho Drizzle: modules/core/db/nuvem.ts, notificacao.recado_do_dia = date('recado_do_dia') (modo string 'AAAA-MM-DD') e notificacao.recado_do_dia_por = uuid('recado_do_dia_por').
- Dicionário: docs/banco/core.md, seção 0021.
- Sem seed (a marcação da demo é feita ao vivo no BKO).
