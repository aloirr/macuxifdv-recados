# CI 2º retrato: conexao-na-transacao reenvio vira conflito porque o teste gera created_offline_at novo a cada push

## Contexto
2º retrato do CI (commit 83b2a89, branch `verificacao/retrato-2026-11-08-1600`, ci.yml run 42520547448). `apps/api/test/conexao-na-transacao.banco.test.ts` (T-0118) cai em "os mesmos pedidos reenviados ao mesmo tempo: aceitos pela idempotência, nenhum duplicado": os 6 reenvios voltam `status: 'conflito'` ("Este pedido já foi recebido com outro conteúdo. Duplique-o para fazer um novo.").

Causa (defeito do teste; a idempotência da produção está certa): o `push(id)` do teste (linha ~62) monta o payload com `created_offline_at: new Date().toISOString()` A CADA chamada. No reenvio o conteúdo muda (outro instante), o hash do envio (`conteudoDoEnvio`, modules/vendedor/domain/aprovacao.ts:611, só tira `total_cents`) difere e o Vendedor responde `conflito` (modules/vendedor/api/receber.ts:274), como deve (RN-VEN-33). O aparelho real reenvia o MESMO payload.

O 1º caso (6 pushes simultâneos com pool 2) passou: a correção do D-T0107a está provada.

## O que preciso
Prioridade alta. Fixar o `created_offline_at` por id (ex.: `const criadoEm = new Map(ids.map((id) => [id, new Date().toISOString()]))` ou uma constante do arquivo) para o reenvio ser byte a byte o mesmo envio.
