# T-0086: backup-dbaas.sh e ensaio-restauracao.sh prontos (interface mantida), opinião sobre a vector e conferências do banco-dbaas.sh

## Contexto
T-0086, resposta ao R-20261105-224337-engenheiro-software. Os dois scripts estão prontos em `db/backup/` (ainda não commitados: o commit é do gerente). A interface do pedido não muda. O que entrou a mais está na lista abaixo e não exige nada do compose, do `implantar.sh` nem do `stack-isolado.yml`.

## Interface final
**`db/backup/backup-dbaas.sh`** (sem argumentos; `MACUXI_DIR`, padrão `/opt/macuxi`; `dc` = `docker compose --env-file .env --env-file imagens.env --profile ferramentas`)
1. **Confere a conexão** pelo `pgcliente`: `pg_stat_ssl.ssl = t`, e o admin com SUPERUSER, BYPASSRLS ou herança USAGE do `macuxi_manutencao`. Sem nenhum dos três, sai com código 2 e nada vai ao bucket.
2. **Faz o dump:** `contagem.sql` → `pg_dump --no-password -d macuxi -Fc -Z 6 --enable-row-security` (stdout → arquivo 600 no host) → `pg_restore -l` (stdin) → `contagem.sql`. Contagem diferente antes e depois: repete até 3 vezes (`MACUXI_BACKUP_TENTATIVAS`, `MACUXI_BACKUP_PAUSA_S`, padrão 30 s). Na última, segue com `estavel=nao` no cabeçalho da contagem.
3. **Envia ao bucket**, com o mesmo carimbo UTC do início do dump:
   - `dc run --rm --no-deps -T backup enviar-contagem --carimbo C` grava `backups/macuxi-C.contagem.txt`;
   - `dc run --rm --no-deps -T backup enviar --carimbo C` grava `backups/macuxi-C.dump` e faz a poda de 30 dias. A contagem sai junto do dump dela.
4. **Última linha:** `[backup-dbaas] <ISO> pronto: backups/macuxi-C.dump (...)`. Falha dá código != 0. Não confere a rota: isso fica no seu `banco-dbaas.sh`. Nenhum segredo é lido: os scripts não abrem o `admin.env` nem o `segredos.env`.

**`db/backup/ensaio-restauracao.sh [ultimo|<chave>]`**
1. **Baixa o backup:** `backup resolver` → `backup baixar` (sha256) → `backup baixar-contagem`.
2. **Monta a lista:** `pg_restore -l`, com o filtro do A9 (sem gatilhos de evento, sem funções pgaudit_ e sem COMMENT ON EXTENSION).
3. **Restaura numa base temporária:**
   - `create database macuxi_ensaio_<AAAAMMDDHHMMSS>` e `create extension if not exists vector`;
   - `pg_restore --no-password --exit-on-error --single-transaction -d <temp> -L /trabalho/lista /trabalho/dump`.
   O `/trabalho` é uma pasta 700 em `/opt/macuxi/backup/ensaio.XXXXXX` (`MACUXI_ENSAIO_TMP`), montada `:ro` no `pgcliente` com `dc run -v`.
4. **Compara:** `contagem.sql` da temporária contra a gravada, e `conferir-rls.sql` da imagem (`--entrypoint cat banco`, como no seu script) com 0 linhas.
5. **Trap EXIT, INT e TERM:** `drop database if exists <temp> with (force)`, com 3 tentativas e conferência em `pg_database`. Só depois disso sai a linha `[ensaio] resultado: IGUAL (...)` com código 0, ou `[ensaio] resultado: DIFERENTE (...)` com código != 0. Base que não saiu também dá DIFERENTE.
6. **Códigos e alcance:** código 2 é erro de uso ou pré-requisito, e aí nada é criado. O script só conecta em `-d postgres` e `-d <temp>`; o `macuxi` nunca é tocado.

## Item 3 (extensão vector)
Deixe o passo no `banco-dbaas.sh`: ele cria a extensão e confere a versão >= 0.8. Não abro migração só para isso agora, porque nenhuma tabela usa vector ainda. Quando entrar a 1ª coluna vector (`catalogo.produto_embedding`), a migração dela traz o `create extension if not exists vector`. Assim o `migrar up` se basta (base de teste, demo recriada, VM nova), e o seu passo continua sem efeito e sem erro: no DBaaS pelo pgextwlist, no CI e na demo como superusuário.

## Item 4 (conferências do `banco-dbaas.sh` × B0 e 0031)
Batem, e não tenho nenhum 🔴 nem 🟡:
- `pg_has_role(current_user, 'macuxi_manutencao', 'USAGE')` é exatamente a filiação `WITH INHERIT TRUE` da 0031.
- `pg_has_role(app|worker, ..., 'MEMBER') = f` é a mesma trava da 0031 (lá, erro 42501).
- LOGIN, sem SUPERUSER e sem BYPASSRLS é o B0.
- O `conferir-rls.sql` vem da mesma imagem das migrações.

🟢 Três detalhes, nenhum bloqueia:
- (a) O `MEMBER` do passo 6 daria erro 42704 se o papel não existisse. Depois do `migrar up` isso não acontece, mas trocar por `exists(select 1 from pg_auth_members ...)` deixaria a mensagem mais clara.
- (b) O `create database macuxi` usa o `template1` padrão. A collation é a do DBaaS, já validada no A12. O ensaio usa o mesmo caminho.
- (c) O `TimeoutStartSec=2h` do `macuxi-backup.service` cobre com folga as 3 tentativas do dump.
