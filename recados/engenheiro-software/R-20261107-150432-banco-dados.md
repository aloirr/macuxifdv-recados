## O que preciso
Que o Core (fatia C), a API (fatia S) e os testes usem exatamente isto. Todas SECURITY DEFINER, `search_path = pg_catalog, plataforma, pg_temp`, `revoke all ... from public` e EXECUTE só ao macuxi_portal (exceto as marcadas).

1. `plataforma.sa_tentativa_estado(p_chave text) returns table (falhas integer, bloqueado_ate timestamptz)` — SEMPRE 1 linha; chave sem registro = (0, null); `bloqueado_ate` só vem preenchido com bloqueio VIVO (> now()). Chave fora de `^[0-9a-f]{64}$` = 22023.
2. `plataforma.sa_tentativa_falha(p_chave text) returns table (falhas integer, bloqueado_ate timestamptz)` — SEMPRE 1 linha. Bloqueio vivo: nada muda, devolve (falhas, bloqueado_ate) atuais. Senão +1; na 5ª seguida: falhas = 0 e bloqueado_ate = now() + 15 min (mesma forma da sa_registrar_falha de hoje: "bloqueou" = bloqueado_ate não nulo). Grava `sa.bloqueio` {minutos: 15} na auditoria (sem chave nem e-mail).
3. `plataforma.sa_tentativa_sucesso(p_chave text) returns void` — zera (apaga o registro) se NÃO houver bloqueio vivo; com bloqueio vivo, nada muda.
4. `plataforma.sa_contas_para_login(p_email text) returns table (tipo text, conta_id uuid, tenant_id uuid, tenant_codigo text, tenant_nome text, senha_hash text)` — no máximo 20 linhas NO TOTAL: primeiro o super-admin (ativo, sem deleted_at; tenant_* nulos), depois os `admin` (ativo, bloqueado_em nulo, senha_hash não nulo, sem deleted_at) de tenant `ativo` sem deleted_at, por `tenant.nome`, `tenant.id`. E-mail comparado por `lower(btrim())`; e-mail vazio/inválido = 0 linhas sem erro. Grava `sa.login.consulta` {contas: n} (sem e-mail).
