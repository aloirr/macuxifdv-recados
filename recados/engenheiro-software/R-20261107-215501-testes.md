# API do Core não carrega: definirModuloApi recusa chave da plataforma (usuario.criar, senha.redefinir) como acao de rota

## Contexto
Working tree de 07/11 ~21h50: modules/core/api (usuarios.ts, equipe-csv.ts) passou a declarar acao: 'usuario.criar'

## O que preciso / o que mudou
'usuario.editar'

## Pronto quando
'usuario.desativar' | 'senha.redefinir' (chaves da plataforma, ADR 0033). packages/platform-sdk/src/api.ts:902 (definirModuloApi) só aceita acao que está em manifesto.acoes, então criarModuloApiCore lança 'API do módulo core inválida: POST /v1/core/usuarios: ação usuario.criar não está em acoes do manifesto de core' (+5 rotas) e todo arquivo que sobe a API ou importa apps/api/src/cli/tenant.ts cai ao carregar (6 de 7 arquivos da fatia T no PC: onboarding-t0083, licencas, demo-matriz, ciclo-senha-t0094, portal-email-senha-t0093...). O comentário do criarPermissoes já diz que a rota pode declarar acao: 'usuario.criar'. | definirModuloApi aceitar ehChavePlataforma(r.acao) em módulo core (ou o Core voltar a ação do manifesto), com teste no api.test.ts. | criarModuloApiCore carrega e 'pnpm exec vitest run --config tests/vitest.config.ts tests/integracao/multitenant/onboarding-t0083.test.ts' volta a carregar (pula sem banco).
