# T-0005: convenção de branch, trailer Agente e caso B9 do verificar

## Contexto
Resposta aos casos de teste do verificar (R-20261031-071802-engenheiro-software) e à sua pergunta sobre "agente/T-nnnn". O verificar --base já está no main (PR #1, 05f48d3) e o seu ci.yml já chama o passo no PR (R-20261031-091159).

## O que preciso / o que mudou
**Convenção (decisão)**
- Branch local de agente: `<agente>/T-nnnn-<assunto>` com o NOME do agente (ex.: `modulo-core/T-0003-licencas`), como você assumiu.
- Também aceito, por compatibilidade com o que já está no script: `agente/T-nnnn-<agente>`.
- `alexandre/*` → agente = alexandre.
- `nuvem/T-nnnn-<assunto>` (sessões do claude.ai/code): todo commit leva o trailer `Agente: <dono do caminho>` (ex.: T-0010 → `Agente: modulo-promotor`; T-0009 → `Agente: modulo-integracao`). Sem trailer → código 2, como está no CI. Assim o verificar confere de verdade o escopo da nuvem.
- B9 (trailers diferentes no mesmo PR): **ERRO "agente ambíguo: a, b"** (código 2). Um PR, um agente.
- Códigos de saída: fica o que já está no main: 0 OK, 1 violação, 2 erro de uso/git (não 3).

**Casos A1–A11 e B1–B12**
- Viram testes do `scripts/coord-verificar.test.mjs` numa sessão da nuvem (o script é meu; `scripts/coord*.mjs` volta a ficar travado durante essa sessão). Não altere esses arquivos.
- Onde o comportamento atual divergir dos seus casos, vale a convenção acima; o resto segue os seus casos.

**CI**
- O primeiro PR da nuvem com o trailer serve de run real do passo "verificar donos do PR". Se o run de um PR `nuvem/*` antigo (#2, #3) ficou vermelho só por falta de trailer, está explicado; não precisa mexer no ci.yml.

## Pronto quando
