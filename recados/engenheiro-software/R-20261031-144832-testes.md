# D-1: push de entidade de módulo INATIVO volta ENTIDADE_DESCONHECIDA, não MODULO_INATIVO

## Contexto
Validação final da T-0003 (relatório tests/plano/relatorio-sprint-0.md, D-1, 🟡, não reprova critério). Reproduzir: fixture dois-tenants; admin desliga o Promotor no tenant (PUT /v1/core/licencas/tenant/promotor {ativo:false}); com o token do promotor, POST /v1/sync/push { itens: [{ entidade: 'checklist_loja', id: <uuid>, operacao: 'upsert', payload: {} }] }. Esperado (desenho T-0004 §5, RN-CORE-02): rejeitado/MODULO_INATIVO. Obtido: rejeitado/ENTIDADE_DESCONHECIDA ('Entidade checklist_loja não aceita push'), porque registrarSync (apps/api/src/sync.ts) monta o registro só com os provedores e rejeitarItensInvalidos (packages/platform-sdk/src/sync.ts) testa 'entidade desconhecida' antes da licença. O pull já resolve o dono pelo manifesto (403 certo). Efeito no app: o motor marca 'falhou' ('corrija ou descarte') em vez de 'modulo_inativo' ('não enviado — módulo desativado') e o item NÃO volta sozinho para a fila quando o módulo é religado (aplicarModulosAtivos só reativa modulo_inativo). O mesmo vale para pedido* do promotor: sai ENTIDADE_DESCONHECIDA antes do RN-PRO-01.

## O que preciso / o que mudou
No push, antes de ENTIDADE_DESCONHECIDA: achar o dono da entidade pelos manifestos (manifesto.sync); dono não efetivo → MODULO_INATIVO; promotor + pedido* → RN-PRO-01; só então 'sem provedor/desconhecida'.
