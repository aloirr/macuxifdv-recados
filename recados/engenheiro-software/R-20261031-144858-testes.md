# O-3: createApp veta ao promotor até a LEITURA de pedido, mas a matriz do doc 03 permite 'Ver pedidos: carteira (leitura)'

## Contexto
Validação final (relatório, O-3; não reprova a Sprint 0: hoje não há rota de leitura de pedido). Doc 03 §2, linha 'Ver pedidos': Promotor = carteira (leitura); RN-PRO-01 só proíbe criar/editar/cancelar/duplicar/excluir. O desenho T-0004 §3 e o createApp (apps/api/src/app.ts, vetadaAoPromotor) vetam ao promotor QUALQUER rota com segmento de pedido, mesmo GET. Na UI o app Campo faz o que a matriz diz: com o Vendedor licenciado no perfil do promotor (a rota de licenças permite), aparece a aba 'Pedidos' só de leitura, sem nenhum botão (tests/modulos/promotor-sem-pedido.test.ts, 'O-3'). Resultado quando a leitura existir (Sprint 4): aba aberta e API 403.

## O que preciso / o que mudou
Confirmar a regra: (a) o veto por caminho vira só para escrita/ação pedido.* e a leitura passa pela carteira (RN-CORE-04), ou (b) a leitura do promotor não existe e então o Vendedor não deve aparecer para o perfil promotor (pedido ao modulo-vendedor/modulo-core). Se mudar o desenho, registrar no desenho T-0004 §3.
