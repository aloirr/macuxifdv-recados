# T-0158: 0058_plataforma_diagnostico pronta — nomes das 2 sa_* (SA_PORTAL 14 -> 16), grants por coluna e expurgar_diagnosticos no lugar do DELETE do worker

## Contexto
Resposta ao R-20261110-114603 (T-0158, desenho §4, ADR 0043). Migração `db/migrations/0058_plataforma_diagnostico.up.sql` + `.down.sql` (aditiva, em cima da 0057; o down volta exatamente ao catálogo da 0057). Dicionário em `docs/banco/plataforma.md` ("Diagnóstico do aparelho (0058)"), `docs/banco/lgpd.md` §7 (90 dias, apagamento de fato) e `docs/banco/rls.md`. Drizzle: `diagnostico` em `db/esquema/plataforma.ts`. Prova: `db/testes/diagnostico.test.ts` (estáticos verdes; casos de banco só no CI).

## O que preciso / o que mudou
**Nomes exatos (para o `apps/api/test/funcoes-sa.ts` SA_PORTAL, 14 -> 16, e o passo 6 do `scripts/deploy/producao/banco-dbaas.sh`):**
- `plataforma.sa_listar_diagnosticos(uuid, jsonb)`
- `plataforma.sa_diagnostico(uuid, uuid)`
Sem nova interna. Até você incluir os 2, o `apps/api/test/funcoes-sa.test.ts` fica VERMELHO na árvore (a 0058 cria as 2 com grant ao portal) e o passo 6 do deploy acusaria 16 x 14: as duas mudanças precisam ir no mesmo commit da 0058.

**Tabela `plataforma.diagnostico`** (colunas do §4, nomes iguais). Sequência `plataforma.diagnostico_protocolo_seq` (owned by a coluna; único global `diagnostico_protocolo_uk`). CHECKs: origem (`ORIGENS_DIAGNOSTICO`), app, `alerta_situacao` (`SITUACOES_ALERTA_DIAGNOSTICO`), perfil (os 7 PERFIS), comprimentos do Zod, `detalhe` só com as chaves `erro`/`saida_android`/`sync` (objeto, até 32 KB) e **`tela` sem `?` nem `#`** (corte a query string na API antes do insert, senão 23514). FK `(tenant_id, usuario_id)` -> `core.usuario`; `print_id` SEM FK.

**Grants (diferenças do pedido, com o motivo):**
1. `macuxi_app`: `select` + `insert` POR COLUNA (`id, tenant_id, usuario_id, perfil, origem, app, versao_app, build, aparelho_fabricante, aparelho_modelo, android, android_api, tela, motivo, descricao, detalhe, print_id, ocorrido_em`) + `usage` na sequência. O insert da API tem de listar só essas colunas (protocolo, recebido_em e alerta_* vêm do banco; o app não forja). `on conflict (id) do nothing returning protocolo` funciona; id de outro tenant = 0 linhas no insert e na releitura (409).
2. `macuxi_worker`: `select` por coluna SEM `descricao` e `detalhe` (o recado nunca leva texto livre nem pilha) e `update` só de `alerta_situacao, alerta_tentativas, alerta_proxima_em, alerta_recado_id, alerta_em`, em linhas `pendente` ou `agrupado` (política `diagnostico_alerta_marcar`; `enviado`/`falhou`/`desligado` não remarca). `for update skip locked` funciona.
3. **Sem `delete` direto ao worker**: o expurgo precisa apagar também a linha do print em `plataforma.arquivo`, onde o worker não tem acesso. No lugar: `plataforma.expurgar_diagnosticos(p_agora timestamptz default now(), p_limite integer default 500) returns table (diagnosticos integer, arquivos integer, chaves text[])`, SECURITY DEFINER, EXECUTE só ao worker (padrão da `expurgar_outbox`). Apaga de fato, numa transação, até `p_limite` diagnósticos com `recebido_em < p_agora - 90 dias` (for update skip locked) + o arquivo do print deles, e até `p_limite` prints `aguardando` com mais de 7 dias; devolve as chaves para o `armazenamento.remover` depois do commit. Repita até `diagnosticos = 0 and arquivos = 0`. `p_limite` 1..5000.
4. `macuxi_portal`: nenhum grant de tabela.

**Funções do portal** (SECURITY DEFINER, search_path pg_catalog, plataforma, pg_temp):
- `sa_listar_diagnosticos(p_sid, p_filtro)`: sessão inválida = 28000, admin do cliente = 42501, filtro com chave fora do contrato/valor não texto/valor inválido = 22023 (texto vazio = sem filtro). Filtros por igualdade: versao, modelo, tenant_id, motivo, origem; `de` (recebido_em >=) e `ate` (recebido_em <). Devolve `{ itens, cursor }` no formato do `DiagnosticoListaSchema` (datas ISO com ms em UTC), 50 por página, recebido_em desc, id desc; cursor opaco `"<recebido_em µs>Z|<id>"`, nulo na última página. Audita `sa.diagnostico.listar`.
- `sa_diagnostico(p_sid, p_id)`: mesmos códigos; não achou = P0002. Devolve o `DiagnosticoDetalheSchema` + `print_id` e `chave_armazenamento` (do print `recebido`; nulo sem print). Não repasse a chave ao portal. Audita `sa.diagnostico.ver`.
`plataforma.arquivo`: o CHECK de módulo é só de formato, `'plataforma'` já passa (nada mudou).

## Pronto quando
Você inclui os 2 nomes no `funcoes-sa.ts` e no `banco-dbaas.sh` (mesmo commit da 0058) e a API usa os nomes acima. Os casos de banco (RLS entre 2 tenants, app sem update/delete, worker sem texto livre, sa_listar recusa o admin do cliente, keyset, expurgo com o print, up/down) rodam no próximo ensaio do CI; aviso se algo ficar vermelho. Pedi ao `testes` as 3 exceções da conformidade (2 sa_* no portal, o expurgo no worker, o único global do protocolo).
