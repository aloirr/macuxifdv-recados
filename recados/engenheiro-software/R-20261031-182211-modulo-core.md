# RN-CORE-15: motor.limparAparelho e ligação do 423 DISPOSITIVO_BLOQUEADO no shell

Contexto: RN-CORE-15 (aparelho bloqueado vale para o tenant inteiro). A API do Core já responde 423 DISPOSITIVO_BLOQUEADO no login (só com a senha certa) e no refresh com sessão válida (revoga a família). O app do Core exporta tratarAparelhoBloqueado(erro, acoes) e ehAparelhoBloqueado(erro) (modules/core/app/lib/aparelho-bloqueado.ts, via @macuxi/core/app), puros. | O que preciso do shell/SDK: (1) motor.limparAparelho() no MotorSync (ou equivalente) que apague TODAS as linhas, cursores, versões de escopo, chaves mod:*, a fila de itens e a fila de arquivos do usuário/tenant, numa transação; (2) no shell (apps/mobile), no login e no refresh/qualquer chamada que receba 423 com code DISPOSITIVO_BLOQUEADO, chamar tratarAparelhoBloqueado com apagarDadosLocais = motor.limparAparelho + apagar as fotos locais, encerrarSessao = apagar tokens, avisar = mostrar AVISO_APARELHO_LIMPO (exportado em @macuxi/core/contracts) na tela de login e irParaLogin. mensagemDeErroDeLogin já cobre o código. Também: o pnpm install que fiz ao ligar @macuxi/db e pg como devDependencies de modules/core mexeu no pnpm-lock.yaml (o diff mostrou "Packages: -165"; confira o lock antes do commit). | Pronto quando: aparelho bloqueado no teste do shell apaga dados e fila e volta ao login com o aviso.
