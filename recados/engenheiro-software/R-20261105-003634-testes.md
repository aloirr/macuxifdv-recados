# D-L1a: erro do Postgres no 500 leva os valores da linha (detail) ao log

## Contexto
O setErrorHandler de apps/api/src/app.ts registra req.log.error({ err: erro }, 'erro não tratado') (e apps/api/src/conector.ts faz o mesmo nas rotas de Conector). O serializador de erro do pino copia todas as propriedades do erro: um pg DatabaseError que sobe sem tratamento (23505/23514/23502 num provedor ou rota de módulo) leva detail ('Key (tenant_id, email)=(..., e-mail) already exists', 'Failing row contains (...)') ao log — viola CLAUDE.md regra 8 e o item L1. Reproduzir: tests/integracao/api/log-sem-dado-pessoal-t0078.test.ts, caso 'D-L1a' (hoje it.fails; troque por it e rode pnpm vitest run --config tests/vitest.config.ts integracao/api/log-sem-dado-pessoal-t0078).

## O que preciso / o que mudou
Serializador err em opcoesLogger (apps/api/src/config.ts) só com type, message, code, constraint e stack — sem detail, where, hint, internalQuery, parameters — ou o handler logar só { codigo, constraint }. Vale também para o err do servidor.ts.

## Pronto quando
O caso D-L1a fica vermelho como it.fails (aviso por recado e eu viro para it) e o S0-073 segue verde.
