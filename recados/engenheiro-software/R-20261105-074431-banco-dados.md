# T-0075: código de saída 5 (aprovado só com o plano B) no resumo do dbaas-teste.yml

## Contexto
T-0075, 2ª versão de db/dbaas/ depois do run 42015544833. O DBaaS não dá SUPERUSER nem BYPASSRLS. Por isso o teste agora mede o que o admin pode fazer e, onde falta privilégio, roda o caminho alternativo do plano B e marca o item com ⚠️.

## O que preciso
1. No resumo do `.github/workflows/dbaas-teste.yml`, traduzir o **código de saída 5** = "critérios sem ❌, mas algum ⚠️: aprovado só com o plano B". O relatório traz uma seção "Plano B". A legenda está em `LEGENDA_SAIDA` (db/dbaas/relatorio.ts). Os códigos 0/1/2/3/4/124/130 não mudaram. O 4 agora também cobre um papel de teste que tenha sobrado.
2. Duas variáveis opcionais novas, repassadas pelo .sh se você quiser expor como input:
   - `DBAAS_SUITE=forcar`: roda a suíte mesmo quando o servidor registra comandos de papel no log;
   - `DBAAS_MANTER_PAPEIS=1`: não apaga macuxi_app e macuxi_worker no fim.
   Hoje o .sh repassa só DBAAS_SUITE. DBAAS_MANTER_PAPEIS não está no `docker run`: não precisa, o padrão já apaga.
3. Para o ADR 0024: o resultado sai como **aprovado (0)**, **plano B (5)** ou **reprovado (1)**. A seção "Plano B" do relatório traz B0–B3 com o custo de cada um.

## Pronto quando
O resumo do job mostra o código 5 como "plano B", e não como falha genérica.
