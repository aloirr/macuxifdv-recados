# T-0003 F2: ErroHttpModulo (401/423) e ctx.dependencias no SDK

## Contexto
Fase 2 da T-0003 em andamento. Dois pontos pequenos no SDK/API que eu preciso e não posso fazer (packages/ e apps/api são seus).

## O que preciso
1. Erro HTTP com status e código para rota pública e privada do módulo (hoje só ErroRegraNegocio=422 e ErroNaoEncontrado=404 chegam ao setErrorHandler com corpo ErroApi). O login precisa devolver 401 `CREDENCIAIS_INVALIDAS` e 423 `USUARIO_BLOQUEADO` (e o refresh 401 `SESSAO_INVALIDA`). Sugestão: exportar do SDK `class ErroHttpModulo extends Error { constructor(status, codigo, mensagem, detalhes?) }` e tratá-lo no setErrorHandler. Até lá o Core lança ErroRegraNegocio (422) com os mesmos códigos e troco quando sair.
2. Dependências entre módulos no contexto da rota: a tela de licenças do BKO precisa avisar "este módulo também desliga: …" (RN-CORE-03) antes de confirmar, e o Core não pode importar manifesto de outro módulo. Peço `ctx.dependencias: Readonly<Partial<Record<ModuloId, readonly ModuloId[]>>>` em ContextoBase (módulo → módulos de `depende`, de todos os manifestos instalados). Até lá `GET /v1/core/licencas` devolve `dependencias: {}` e o aviso fica vazio.
3. Para ciência: `servicos.autenticar` do Core consulta core.usuario (ativo/bloqueado/perfil) a cada requisição, então perfil e bloqueio remoto valem na hora; o JWT carrega só sub/tid/perfil/exp. O segredo vem de MACUXI_JWT_SEGREDO (mín. 32 caracteres; sem ele o login responde 503 e a API segue falhando fechada). Peço incluir essa variável no .env.example e no servidor.ts quando o Core estiver pronto.
4. Testes ponta a ponta com createApp (login → /v1/me/modulos → 403 MODULO_INATIVO) ficam fora de modules/core por causa das fronteiras: o Core entrega `moduloApi` com a fábrica `criarModuloApiCore(deps)` (deps injetáveis: segredo, relógio, repositório) e testa os handlers direto; a montagem com createApp em apps/api/test/core.test.ts é sua (ou do testes).

## Pronto quando
Itens 1 e 2 no SDK/app.ts; item 4 combinado.
