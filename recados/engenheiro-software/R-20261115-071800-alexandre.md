# BKO: rotina "Upload massivo de fotos de produto" (ZIP; o nome do arquivo é o código do produto)

## Mensagem do dono do produto (chat, 15/11/2026 ~7h18 de Manaus)
> "As fotos do produto podem subir conforme uma rotina do bko chamada Upload massivo de fotos de produto. Será um arquivo ZIP com todas as fotos. Para atrelar as fotos ao produto, a foto precisará ter o mesmo código. Crie essa tela no web bko e me mande aqui como ficará"

## O que fica decidido (entra na esteira)
- Rotina nova no BKO, no Catálogo: upload de **um ZIP** com as fotos dos produtos.
- A foto entra no produto cujo **código é igual ao nome do arquivo**, sem a extensão.

## Simulação da ponte, enviada ao dono do produto (aguarda o ok dele)
`recados/anexos/R-20261115-071800-upload-fotos.png` (neste repositório).
- **A (antes de enviar):**
  - área "Arraste o arquivo ZIP aqui" com o botão "Escolher arquivo ZIP" e o limite de 500 MB;
  - três regras: nome = código (`PAF.1434.jpg` → PAF.1434); JPG, PNG ou WEBP, com pastas aceitas; mais de uma foto como `PAF.1434_2.jpg`, sendo a sem número a principal;
  - chave "Trocar as fotos que o produto já tem", desligada por padrão;
  - botão "Enviar".
- **B (resultado):**
  - três números: fotos ligadas, sem produto com esse código, arquivos recusados;
  - tabela "para corrigir" com arquivo, problema e o que fazer;
  - "Baixar lista (CSV)" e "Enviar outro ZIP".

## Pontos em aberto com o dono do produto (a ponte confirma; não implementar antes)
1. Mais de uma foto por produto (`_2`, `_3`). Hoje a API só tem a foto principal (`PUT produtos/:id/foto-principal`, `catalogo.produto_midia`).
2. Limite de 500 MB por ZIP.
3. Comparar o nome com o código sem diferenciar maiúsculas e minúsculas.
