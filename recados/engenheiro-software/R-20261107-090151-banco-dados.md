# T-0089 B2: views-modelo do Conector (15 entidades) e teste contra o SCHEMA_REGISTRO — revisão

## Contexto
T-0089, fatia B2 (docs/desenho/T-0089.md, tabela de fatias), que ficou aberta no meu R-20261106-184517 (resposta ao seu R-20261106-073325). O arquivo das views-modelo do Conector não existia; agora existe, com as 15 entidades.

## O que preciso (revisão)
**Arquivos:**
- `db/conector/views-modelo.sql` (novo): uma view `vw_macuxi_<entidade>` por entidade do Hub, na ordem do `ORDEM_CARGA` (`apps/conector/src/config/entidades.ts`), com a `tabela_escalonada` depois do `preco`.
- `db/testes/views-modelo-conector.test.ts` (novo, sem banco, 66 casos): lê o `SCHEMA_REGISTRO` pelo import público `modules/integracao/contracts`.
- `docs/banco/integracao.md`, seção "Views-modelo do Conector": formato atualizado.

**Decisões para conferir:**
1. **Coluna = nome do campo do contrato**, todas as obrigatórias e também as opcionais. Objeto aninhado vira `<objeto>_<campo>` (`endereco_cidade` → `"endereco.cidade"`), e lista vira uma coluna JSON com o nome do campo. Assim a consulta do `conector.json` fica `SELECT * FROM vw_macuxi_<e>` e o mapeamento fica 1 para 1.
2. **Dialeto:** o corpo ativo é SQL Server 2017+. Cada divergência traz a forma Oracle 12.2+ comentada (`-- [Oracle]`) acima da linha `-- [SQL Server]`. Divergem: `alterado_em` (`DATETIME2(3)` × `TIMESTAMP(3)`/`SYS_EXTRACT_UTC`), data civil (`CONVERT(...,23)` × `TO_CHAR`), `CONCAT` × `||`, e `STRING_AGG`/`FOR JSON PATH` × `LISTAGG`/`JSON_ARRAYAGG`. Iguais nos dois: dinheiro `CAST(ROUND(x*100,0) AS DECIMAL(19,0))`, booleanos por `CASE` e `external_id` como `CAST(... AS VARCHAR(200))`.
3. **Data civil sai como texto `AAAA-MM-DD`**, no fuso do tenant e sem UTC, em vez de `DATE`. Assim não depende de como o driver devolve `DATE`.
4. **Cliente:** `formas_pagamento` sem linha devolve `'[]'`, que limpa (todas as formas); se o ERP não controla formas, a coluna fica NULL, que não altera. `prazo_medio_max_dias` NULL não limpa, porque o Conector omite nulos; o modelo sugere 365 para "sem teto".
5. **O teste é estrito:** também falha se o contrato ganhar um campo OPCIONAL sem a view, ou se a view tiver uma coluna fora do contrato. Isso vai além do pedido, que falava só das obrigatórias. Se preferir só as obrigatórias, eu afrouxo.
6. **Pendências:** nenhuma; as 15 views estão no arquivo.

**Testes:** `pnpm --filter @macuxi/db` lint (0 erros; 7 avisos antigos), typecheck e o teste novo verdes. Não há caso de banco: as views rodam no banco do ERP, e não temos SQL Server nem Oracle no CI.
