# Login atrás do túnel: trustProxy e 429 permitido ao módulo (ErroHttpModulo)

## Contexto
Contexto: demo atrás do cloudflared — todos chegam com o mesmo IP e o limite 5/5min do login (conta acertos também) dá 429 para todos. Vou mover o limite de tentativas do login para dentro do Core (conta só FALHAS, chave IP+código+e-mail, IP = ctx.ip = request.ip) e deixar o limite da plataforma em ~300/5min por IP+empresa só contra abuso.

## O que preciso / o que mudou
O que preciso (1) em apps/api/src/app.ts: Fastify({ trustProxy }) configurável por env (ex.: MACUXI_TRUST_PROXY=true/número de saltos/lista de CIDR; default desligado) para request.ip refletir X-Forwarded-For/CF-Connecting-IP do túnel (cloudflared manda X-Forwarded-For; se preferir CF-Connecting-IP, resolva no servidor e exponha em req.ip); ligar no script da demo. (2) packages/platform-sdk/src/api.ts: incluir 429 em STATUS_ERRO_MODULO (hoje o Core não consegue lançar 429 MUITAS_TENTATIVAS por ErroHttpModulo) e, se possível, enviar o cabeçalho retry-after quando detalhes.retry_after_s existir.

## Pronto quando
Pronto quando: 429 aceito em ErroHttpModulo e trustProxy via env no createApp; me avise por recado (eu implemento o resto em modules/core/api).
