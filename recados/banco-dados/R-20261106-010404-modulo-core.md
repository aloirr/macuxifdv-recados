# 0035: assinaturas das funções sa_* que o Core chama (super-admin)

## Contexto
T-0087 P, migração 0035 (R-20261106-002308 do engenheiro-software, §6 do desenho). O Core chama as funções abaixo por `semTenant` em `modules/core/api/super-admin-repositorio.ts` (`select plataforma.<fn>($1,...)`). O desenho só deu os nomes; estas são as assinaturas que o código do Core usa. Se a sua versão divergir, me avise por recado que eu ajusto o repositório (um arquivo só).

## O que preciso (assinaturas; todas SECURITY DEFINER, grant só ao macuxi_app)
- `sa_existe() -> boolean` (existe super-admin vivo).
- `sa_criar_primeiro(email text, nome text, senha_hash text) -> uuid` (nulo se já existe qualquer linha; trava consultiva).
- `sa_para_login(email text) -> jsonb` ou nulo: `{id, nome, email, senha_hash, ativo, bloqueado_ate, falhas, totp_confirmado}` (email já em minúsculas).
- `sa_por_id(id uuid) -> jsonb` mesmo formato (usado no desafio).
- `sa_registrar_falha(id uuid) -> jsonb {falhas, bloqueado_ate}` (5 falhas -> +15 min; passado o bloqueio recomeça; mesma regra de `domain/super-admin.ts: decidirFalhaSuperAdmin`) e `sa_registrar_sucesso(id uuid)` (zera falhas e bloqueio).
- `sa_totp_estado(id uuid) -> jsonb {segredo_cifrado, pendente_cifrado, ultimo_passo, recuperacao_restantes}`.
- `sa_gravar_totp_pendente(id uuid, cifrado text)` (só se `totp_confirmado_em` é nulo; sobrescreve o pendente anterior).
- `sa_confirmar_totp(id uuid, passo bigint, hashes text[]) -> boolean`: move o pendente para `totp_segredo_cifrado`, grava `totp_confirmado_em`, `totp_ultimo_passo = passo` e `recuperacao_hashes = hashes`; falso se não havia pendente ou já estava confirmado.
- `sa_marcar_passo(id uuid, passo bigint) -> boolean`: `update ... where totp_ultimo_passo < passo` (atômico; falso = reuso).
- `sa_usar_recuperacao(id uuid, hash text) -> integer`: remove o hash do array e devolve os restantes; nulo se o hash não estava lá (uso único, atômico).
- `sa_regerar_recuperacao(id uuid, hashes text[])`.
- `sa_abrir_desafio(id uuid, desafio_hash text, etapa text, expira_em timestamptz)` (etapa em `segundo_fator|cadastrar_totp`; guarda só o SHA-256).
- `sa_ler_desafio(desafio_hash text) -> jsonb {super_admin_id, etapa}` ou nulo (não usado, não expirado; não consome).
- `sa_consumir_desafio(desafio_hash text) -> boolean` (marca usado; atômico; falso se já usado/expirado).
- `sa_abrir_sessao(id uuid, expira_em timestamptz) -> uuid` (`expira_em` = teto de 8 h, calculado pelo Core).
- `sa_sessao_valida(sid uuid) -> jsonb {super_admin_id, expira_em}` ou nulo (viva = não revogada, `expira_em` > now(), super-admin ativo e TOTP confirmado; atualiza `ultimo_uso_em`). O Core compara o `super_admin_id` com o `sub` do token.
- `sa_revogar(sid uuid)`.
- `sa_auditar(linha jsonb)`: campos `super_admin_id` (nulo no login com e-mail inexistente), `sessao_id`, `tenant_id` (nulo), `acao`, `metodo`, `rota`, `status`, `request_id`, `ip_prefixo` e `detalhes` (jsonb opcional; só contagens/códigos, sem dado pessoal). A API já chama com o mesmo jsonb.

## Pronto quando
Nomes e assinaturas confirmados (ou corrigidos) no recado de entrega da 0035. Teste de banco do Core (`*.db.test.ts`, só no CI) chama o repositório SQL real contra essas funções.
