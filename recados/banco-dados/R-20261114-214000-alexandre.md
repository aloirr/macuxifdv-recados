# Deploy da v1.0.9 espera o login (#285); kit de integração da thathyany no notebook, com o Python de carga por CSV

## Mensagens do dono do produto (chat, 14/11/2026 ~21h30–21h40 de Manaus)
> "Agora preciso configurar à empresa Thathyany em meu notebook, para integrar via conector e via api o banco e o erp e testar 100% a operacao"
>
> Pergunta da ponte: o deploy espera o #285 (A) ou sai sem ele (B)? Resposta: "A"
>
> "Quero testar com a thathyany, pois ela é minha segunda empresa e posso mexer nela. crie o kit para ela. incluindo uma aplicação python que me permita subir todas as tabelas via csv para o banco, para agilizar."

## O que fica decidido
1. **Deploy da v1.0.9 só com o #285 (login) no main**, verde, com o corretor sem achado. Depois do deploy roda o `producao-codigo-licenca` com `simular=true`, o código novo vai ao dono do produto e em seguida roda de verdade.
2. **O teste de integração é na thathyany**, a empresa real dele. Ele autoriza mexer nos dados dela. O teste não usa as empresas "Piloto".
3. **Kit da thathyany para o notebook**, a partir do kit piloto (`modules/integracao/kit-piloto/`, `docs/modulos/integracao/kit-piloto.md`):
   - Banco do ERP local em SQL Server Express, com as views `vw_macuxi_*` (`db/conector/views-modelo.sql`) e a entrada de pedidos (`db/conector/entrada-pedido-modelo.sql`).
   - **Aplicação Python de carga por CSV:**
     - sobe todas as tabelas para o banco local de uma vez: um CSV por entidade, na ordem de carga, com as colunas do contrato (`docs/modulos/integracao/carga-arquivo.md`);
     - acompanha modelos de CSV com cabeçalho e uma linha de exemplo fictícia;
     - valida antes de gravar (obrigatórios, centavos, datas UTC);
     - grava de forma idempotente por `external_id`;
     - mostra um relatório por tabela.
   - **Conector e API em fases**, por causa da RN-INT-13 (uma fonte por entidade e uma só integração recebe pedidos por empresa):
     - fase 1: Conector com todas as entidades e os pedidos;
     - fase 2: desativa o Conector e liga a API com outra credencial, com o mesmo teste.
     - Cada fase tem um roteiro passo a passo, do pedido no app ao número do ERP voltando.
   - Os endereços apontam para `https://api.macuxifdv.com.br`. A demo foi desligada.
   - O pacote do Conector 1.4.0 vai no kit. Publicar o Conector na produção (`conector-publicar`) ainda **não** está autorizado. Se o kit precisar disso, peça a decisão ao dono do produto pela ponte.
4. **Pendências que o kit expôs, para o time tratar dentro do mesmo pedido:**
   - os exemplos da API e o kit ainda apontam para a demo;
   - nenhum workflow gera o zip do kit;
   - o roteiro 1.4.0 diz "chave gerada no BKO", mas a chave é gerada no portal.
5. Antes de ir ao dono do produto, o kit passa pelo corretor e pelo testes. A marca valida se houver tela ou documento com a marca.

## Pronto quando
O dono do produto recebe:
- o zip do kit;
- o Python de carga com os modelos de CSV;
- o roteiro das duas fases para rodar no notebook;
- a lista do que ele precisa ter em mãos: o ERP e o banco dele, a chave gerada no portal e o código novo da thathyany depois do deploy.
