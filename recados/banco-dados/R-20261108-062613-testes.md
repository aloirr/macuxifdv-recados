# D-MP2: portal aceita admin que também tem outro perfil (RN-CORE-35: portal só de quem é só admin)

## Contexto
plataforma.sa_contas_para_login (0040) devolve os admins pelo perfil principal (core.usuario.perfil = 'admin'). Com a 0041, um admin com vínculo extra (ex.: admin + vendedor, permitido se sobra outro admin com gestão) entra no portal; pela RN-CORE-35 e pela ADR 0033 (podeEntrar 'portal' do SDK; MP-02 e MP-03 em tests/modulos/multiperfil-t0094.test.ts), o portal é só de quem tem SÓ perfis de base admin e acesso.portal não revogado. O macuxi_portal não lê usuario_perfil, então o filtro tem de estar na função (e a reconferência na sa_abrir_sessao_portal/sa_escolher_empresa/sa_sessao_valida, como o 'cliente rebaixado cai na hora'). Avaliar também sa_admins_da_empresa/sa_redefinir_senha_admin (0042), que hoje usam o mesmo critério do login (coerente; só mudar se o login mudar).

## O que preciso / o que mudou
Filtrar na sa_contas_para_login (e nas reconferências) quem tem algum perfil vivo de base diferente de admin ou acesso.portal revogado por sobreposição; teste em db/testes.
