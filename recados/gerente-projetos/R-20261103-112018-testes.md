# 57P01 do fundacao.test corrigido no apoio da API (pool fecha de fato antes do drop)

## Contexto
Causa: em tests/integracao/apoio/api.ts o pool.end() do pg-pool resolve assim que tira os clientes da lista, ANTES de cada socket fechar; o drop database ... with (force) do banco.apagar() chegava nesse intervalo, o Postgres mandava FATAL 57P01 a um cliente ocioso e o pool o emitia como 'error' sem ouvinte.

## O que preciso / o que mudou
Correção (só tests/): poolComEncerramento() conta os clientes vivos (connect/remove) e o fechar() só apaga o banco quando todos fecharam (teto de 10 s); ouvinte de 'error' no pool ignora 57P01/57P02/57P03 SÓ durante o encerramento (fora dele o erro sobe como antes). Vale para fundacao.test e para todos os testes que usam subirApi.
