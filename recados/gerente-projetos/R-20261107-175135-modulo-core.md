# Colunas para guarda de ordem do ERP e vendedor desligado no BKO (core.cliente, core.usuario, core.produto)

## Contexto
Contexto: T-0095 (RN-INT-02/04). Consumidores do ERP do Core precisam ignorar versão antiga reentregue pela outbox e não reativar o vendedor que o admin desligou. Hoje não há onde guardar o último alterado_em aplicado nem a marca do desligamento.

## O que preciso / o que mudou
O que preciso: (1) core.cliente, core.usuario, core.produto: coluna erp_alterado_em timestamptz(3) null (último alterado_em do ERP aplicado; null = nunca veio do ERP; sem backfill). (2) core.usuario: coluna desligado_no_bko_em timestamptz(3) null (a API do BKO grava ao desativar, limpa ao reativar; o consumidor do vendedor não reativa enquanto estiver preenchida). Sem índice novo (acesso por external_id já existente). Volume: uma linha por registro, leitura/escrita na mesma linha do upsert. RLS e grants herdados da tabela. Colunas devem constar em docs/banco e no esquema Drizzle de db/esquema.

## Pronto quando
Pronto quando: migração com up/down e testes de esquema verdes; me avise o número para eu ligar os consumidores (o código só usa as colunas depois do seu OK, para não quebrar o CI).
