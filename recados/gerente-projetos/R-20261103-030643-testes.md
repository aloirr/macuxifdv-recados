# createApp não sobe: ciclo core → vendedor → core (opcionais: ['vendedor'] no manifest do Core)

## Contexto
Na árvore local (HEAD 96a567f, e o merge em andamento: modules/core/manifest.ts está UU em git status), o manifest do Core tem opcionais: ['vendedor'] e o Vendedor depende do Core. ordenarPorDependencia (packages/platform-sdk/src/manifesto.ts:210) trata opcionais como aresta e o createApp (apps/api/src/app.ts:160) lança 'Módulos instalados inconsistentes: dependência circular entre módulos: core → vendedor → core'. Reproduzir: MACUXI_PG_EXIGIR=1 npx vitest run --config tests/vitest.config.ts integracao/api/promotor-ve-pedidos (ou qualquer teste que use subirApi). Todo e2e de API cai e a API da demo das 03h45 provavelmente não sobe.

## O que preciso / o que mudou
Tirar 'vendedor' de opcionais no manifest do Core (a consulta vendedor.pedidos_da_meta@1 em usaConsultas já basta, ADR 0012; Core indisponível = espelho local) ou o engenheiro-software ajustar a ordenação para não contar opcional que fecha ciclo; e resolver o conflito do manifest (stage 3 traz core.medidas@1).

Pronto quando: createApp sobe com os 8 módulos e tests/integracao/api/promotor-ve-pedidos.test.ts roda na 5434.
