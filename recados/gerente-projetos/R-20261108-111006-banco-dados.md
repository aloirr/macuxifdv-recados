# 0047: suporte lista e redefine a senha de quem tem algum perfil de base admin (resto do D-MP2), lista com entra_no_portal

## Contexto
Resto do D-MP2 (T-0094/T-0111), apontado na minha entrega da 0046 (R-20261108-101610): a 0042 decidia "é admin" pelo perfil PRINCIPAL em `sa_admins_da_empresa` e `sa_redefinir_senha_admin`. Decisão do gerente: igual ao SDK e à ADR 0033, entre perfis de base admin vale a soma; admin + qualquer base não admin fecha o portal.

## O que foi feito
Migração `0047_plataforma_portal_admin_multiperfil` (em cima da 0046; só funções, nenhuma tabela, índice, política, papel ou grant novo):
1. `plataforma.usuario_tem_perfil_admin(p_tenant uuid, p_usuario uuid) -> boolean`: algum perfil vivo e ativo de base admin (os mesmos perfis de `perfis_do_usuario` e da `usuario_entra_no_portal`). É o complemento exato do BKO (o SDK recusa `senha.redefinir` em alvo com algum perfil de base admin): o suporte alcança quem o BKO não alcança, sem buraco nem sobreposição. SECURITY INVOKER, stable, search_path fixo, sem EXECUTE para app, worker, portal e PUBLIC. Sem prefixo `sa_` (SA_PORTAL/SA_INTERNAS e banco-dbaas.sh não mudam).
2. `sa_admins_da_empresa(p_sid, p_tenant)`: mesma assinatura; o retorno GANHA a última coluna `entra_no_portal boolean` (drop + create, revoke/grant iguais: EXECUTE só ao macuxi_portal). Lista quem tem algum perfil de base admin (admin principal, admin extra, admin + vendedor, personalizado de base admin). `entra_no_portal` = `plataforma.usuario_entra_no_portal` (0046). A coluna fala só dos perfis; ativo, bloqueado, tem_senha e trocar_senha completam se a conta entra de fato.
3. `sa_redefinir_senha_admin(...)`: mesma assinatura e retorno (create or replace). O alvo passa a ser quem tem algum perfil vivo e ativo de base admin, mesmo que o principal seja outro (vendedor principal + admin extra agora é resgatável). O resto é o texto da 0042, letra por letra (o teste estático confere as trocas exatas).
4. Mantidos: SECURITY DEFINER, `search_path = pg_catalog, plataforma, pg_temp`, EXECUTE só ao macuxi_portal, 14 `sa_*` (conferência pelo catálogo no fim do up e do down, que aborta com 42501). Down: recria as 2 com o texto EXATO da 0042 (a lista volta às 9 colunas) e apaga a função nova; volta ao catálogo e às ACLs da 0046.

RN-CORE-35, regra mais restritiva: conferida, NÃO muda o alvo. Ela vale para os ACESSOS (entrar no BKO e no portal), não para as ações. Redefinir a senha é ação do super-admin sobre a conta e não dá acesso nenhum: admin + vendedor segue sem portal (0046) e sem BKO (0041/SDK), e troca a senha no próximo acesso pelo app. Aplicá-la ao alvo ("só quem é só admin") devolveria o buraco: admin + vendedor fora do suporte e fora do BKO. Onde ela entra é na coluna `entra_no_portal`.
