# configurar-dominio.ps1 não acha o túnel que acabou de criar: deleted_at "0001-01-01T00:00:00Z" é tratado como apagado

## Contexto
Rodei `_instalar\configurar-dominio.cmd` (login da Cloudflare OK, domínio ativo). 1ª vez: "ERRO: O túnel macuxi-demo foi criado, mas não aparece em cloudflared tunnel list. Rode de novo em 1 minuto." 2ª vez: "ERRO: cloudflared tunnel create falhou (código 1): failed to create tunnel: Create Tunnel API call failed: tunnel with name already exists". Ou seja: o túnel macuxi-demo EXISTE na conta, mas o script nunca o enxerga.

## O que preciso / o que mudou
Causa provável (scripts/demo/tunel.ps1, Listar-Tuneis, linha ~104): o `cloudflared tunnel list --output json` devolve `"deleted_at": "0001-01-01T00:00:00Z"` (tempo zero do Go) para túnel ATIVO. O filtro `-not (($nomes -contains 'deleted_at') -and $t.deleted_at)` considera essa string (ou o DateTime do ano 1, no PowerShell 7) como verdadeira e descarta o túnel. Além disso, a listagem sem `--show-deleted` já não traz túnel apagado.
1. Corrija: túnel apagado só quando `deleted_at` existir, não for vazio e não for o tempo zero (string começando com "0001-01-01" ou DateTime com Year -le 1). Vale para o configurar-dominio e para o subir-demo (mesma função).
2. Teste com a saída JSON real do cloudflared (deleted_at zero → ativo; data real → apagado; sem o campo → ativo), em PowerShell 5.1 e 7 se o teste já cobre os dois.
3. Mensagem de erro: se o `tunnel create` responder "already exists" e a lista não achar, diga isso com clareza (em vez de mandar esperar 1 minuto).
4. Commit e push assim que estiver verde (exceção da rotina de 2 h: está bloqueando a demo) e me avise por recado. Eu rodo o atalho de novo: o túnel macuxi-demo já criado deve ser reaproveitado, sem criar outro.

## Pronto quando
`_instalar\configurar-dominio.cmd` rodado de novo reaproveita o macuxi-demo, cria o DNS de api-demo e bko-demo e grava o config.yml; teste cobrindo o deleted_at zero.
