# T-0002: compose, migrações up/down, RLS, seed Fase M, fixture e docs (validado em Postgres embutido; falta Docker)

## Contexto
T-0002 — infraestrutura de banco escrita para rodar quando o Docker estiver de pé. Sem commit.

## O que preciso / o que mudou
**Feito**
- `db/docker-compose.yml` (serviço `postgres`, `pgvector/pgvector:pg16`, volume, UTC, healthcheck). `docker-compose.yml` da raiz é do engenheiro: pedido R-20261031-073127 (include opcional).
- Pacote `@macuxi/db` (`db/package.json`, tsconfig, vitest) + CLI `pnpm --filter @macuxi/db banco subir|derrubar [--limpar]|status|papeis|migrar up|down|seed fase-m|fixture dois-tenants|criar-teste|apagar-teste`.
- Migrações SQL com caminho de volta: `db/migrations/0001_plataforma` (tenant, tenant_modulo, perfil_modulo, usuario_modulo, evento, parametro, auditoria) e `0002_core` (usuario, equipe, produto conforme ADR-0005, cliente, carteira). Executor com checksum (migração aplicada não pode ser editada) e advisory lock.
- RLS: ENABLE + FORCE em todas, política `isolamento_tenant` para `macuxi_app` com `plataforma.tenant_atual()` (falha fechada: sem contexto = 0 linhas; não-UUID = erro). Papel `macuxi_app` sem SUPERUSER/BYPASSRLS e não dono. FKs compostas (tenant_id, x_id). Auditoria só SELECT/INSERT. Login via `plataforma.tenant_por_codigo` (SECURITY DEFINER).
- Drizzle: `drizzle.config.ts`, `db/esquema/plataforma.ts`, `modules/core/db/nuvem.ts` (espelho tipado; teste compara com o banco).
- Seed Fase M (`db/seeds/fase-m/fase-m.ts`: 12 usuários, 6 equipes sob a gerência, 60 produtos, 18 clientes e carteira, módulos e parâmetros padrão; idempotente) e fixture dois-tenants (`db/seeds/fixtures/dois-tenants.ts`).
- Docs: `docs/banco/README.md` (subir, testar, derrubar, o que falta), `rls.md`, `plataforma.md`, `core.md`, `fixture-dois-tenants.md`.
- Testes `db/testes/`: estático (sempre roda, 39 casos) + migracoes (S0-020/021/022), conformidade (S0-023/028), vazamento (S0-024/025/026/027), seed-fase-m (S0-031..034), drizzle-x-banco. Sem Postgres pulam com aviso; `MACUXI_PG_EXIGIR=1` faz falhar (CI).

**Verificação feita sem Docker**: typecheck e lint do db/ limpos e suíte completa rodada num Postgres 16.15 embutido TEMPORÁRIO no scratchpad (fora do repo, já desligado), com as dependências instaladas lá: **71 passaram, 1 pulado (pgvector, só existe na imagem Docker)**; CLI exercitado (migrar up/down, seed 2×, fixture, criar/apagar teste, status). `pnpm lint`, `pnpm typecheck`, `pnpm test` da raiz verdes; `verificar banco-dados` sem violação em arquivo meu (as listadas são de outros donos).

**Pendências / o que falta executar quando o Docker subir**
1. Engenheiro incluir `db` no `pnpm-workspace.yaml` + `pnpm install` (R-20261031-073127). Até lá o `@macuxi/db` não entra no turbo (por isso a raiz segue verde sem rodar os testes do banco).
2. `pnpm --filter @macuxi/db banco subir` → `pnpm --filter @macuxi/db test` sem pulos (inclui o teste de pgvector) → `banco seed fase-m`.
3. Testes confirmar que roda a partir de tests/ — só então encerro R-20261030-235502 (respondido em R-20261031-073126, sem encerrar).
4. EXPLAIN do sync pull/carteira com volume (meta p95 < 300 ms) quando houver dados e a rota de sync.
5. Decisão sobre o despacho do outbox (pg-boss) cruzando tenants: proposta em docs/banco/rls.md, com o engenheiro.
