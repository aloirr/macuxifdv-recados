# T-0075: apagar() da base efêmera sem superusuário (42501 no DROP ... WITH (FORCE) do CI 6cbcd87)

Contexto: CI do main 6cbcd87 (run 42159762560) vermelho só no job "testes do @macuxi/db com admin sem superusuário (simula o DBaaS)": db/testes/nota-erp-vendedor.test.ts > "0025 EXPLAIN com volume (banco efêmero)", afterAll -> b.apagar() -> apagarBanco -> `drop database ... with (force)` = 42501 "permission denied to terminate process". Causa: sem superusuário o FORCE só encerra sessão de papel de que o admin tem privilégio (INHERIT) ou com pg_signal_backend; o admin tem só SET (sem INHERIT) no macuxi_app/macuxi_worker (B0). O `client.end()` do pg resolve quando o socket fecha, antes de o backend do macuxi_app sumir do servidor (ou havia um autovacuum worker, sem papel, na base): corrida intermitente. O FORCE checa tudo antes de sinalizar, então falha inteiro.

O que fiz:
- db/src/apagar-banco.ts (novo): `apagarBancoForcado(c, nome, { prazoMs })`. Tenta `drop ... with (force)`; com 42501 e sessão na base faz o DROP comum (o Postgres encerra o autovacuum e espera até 5 s, sem privilégio de sinal) e repete com espera 100/200/400/800/1000 ms até 30 s. 42501 duas vezes sem ninguém na base = falta de privilégio real -> erro original sobe. Prazo vencido -> erro com code 42501 e o resumo de quem segura a base (papel/tipo e quantidade, sem query nem dado pessoal): conexão vazada continua falhando. Com superusuário o 1º DROP passa (sem mudança).
- db/src/banco-teste.ts: apagarBanco (e portanto `BancoDeTeste.apagar()`, usado pelo db/testes, pelo globalSetup e pelo tests/ via @macuxi/db/teste) usa a função.
- db/dbaas/teste-compatibilidade.ts: apagarBaseDireto (L1/L1.2 no DBaaS real) usa a mesma função.
- Não concedi pg_signal_backend nem filiação com INHERIT ao admin (as políticas "to macuxi_app" passariam a valer para ele; e o DBaaS real não dá pg_signal_backend garantido). Job não afrouxado.
- Outros padrões: nenhum outro DROP com FORCE em TS do @macuxi/db; db/scripts/limpar-bancos-teste.mjs é só host local (superusuário), mantido; apps/conector/test/integracao.pg.test.ts (modulo-integracao) usa root e não roda no job sem superusuário.
- db/testes/apagar-banco.test.ts (novo, sem banco, 10 casos): roteiros com cliente falso (superusuário, sessão saindo, espera crescente, sessão já saiu, privilégio real, conexão vazada com mensagem, outro erro sobe na hora, nome inseguro, tabela de espera) + trava estática: nenhum `drop database ... ${x} with (force)` em src/, dbaas/, scripts/, seeds/, testes/ fora de src/apagar-banco.ts.
- docs/banco/README.md: item "Apagar a base efêmera sem superusuário".

Testes: db/testes/apagar-banco.test.ts 10/10 local (sem banco); typecheck e lint do @macuxi/db verdes; verificar banco-dados sem violações. Testes de banco só no CI.

Pronto quando: o job sem superusuário fica verde de forma estável no próximo lote (a corrida é intermitente: o critério é ele não repetir o 42501; se repetir depois de 30 s, a mensagem mostra qual papel segura a base = conexão vazada de teste, a corrigir no teste).
Pendências: nenhuma minha. Caixa com recados antigos fora do escopo desta tarefa não tratados nesta rodada.
