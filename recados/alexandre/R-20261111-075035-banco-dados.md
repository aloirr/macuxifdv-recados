# T-0119: gargalo da busca de 20 mil é o Node (índice refeito a cada 60 s trava o event loop), não o banco — sem 0062; estático dos índices e pedido ao modulo-catalogo

## Contexto
T-0119 (D-T0107b): busca da API com 20 mil produtos, meta p95 < 300 ms. Tarefa do banco-dados: achar o gargalo pelo plano e propor ou aplicar o índice.

## O que fiz
- **Diagnóstico: o gargalo não é o banco.** CI `main` 43008008751 (`busca-volume.db.test.ts`): caminho completo `9 22 44 327 384 472 521 587 602 828` ms, p95 828 ms. O mesmo caminho rodado só em memória, sem banco, com perfil de CPU no PC, gasta 180–1400 ms por consulta de texto em `candidatosDaBusca` (o pior caso é o erro de digitação), `cortarCandidatos` e `buscarProdutos`. Os 200 candidatos são renormalizados a cada consulta.
- **Causa provável do p95 de 15–20 s na carga:** o índice em memória (`construirIndiceBusca`, ~39 s no PC) é refeito a cada retrato novo (TTL de 60 s), em CPU síncrona, e trava o event loop da API para todas as requisições.
- **Leituras de banco da busca, todas por índice:** `precos` → `tabela_preco_item_filial_vigencia_uk`; `saldos` → `estoque_saldo_produto_ix` + PK de `deposito`; tabela do cliente → `cliente_tabela_preco_cliente_uk`; retrato → os `*_uk (tenant_id, produto_id)`. O EXPLAIN sem Seq Scan do teste 1 passa no CI. **Sem migração 0062**: um índice novo não teria efeito e só pesaria na carga do ERP.
- **Teste estático novo** `db/testes/busca-catalogo-indices.test.ts` (8 verdes): trava o estado final desses 7 índices (tabela, colunas iniciais e predicado parcial) e a PK do depósito.
- **Docs:** seção "T-0119" em `docs/banco/catalogo.md`.
- **Recado R-20261111-073120-banco-dados** ao modulo-catalogo (cc gerente), com 3 correções no código dele: (1) retrato com stale-while-revalidate e troca só se o catálogo mudou, com a consulta exata de versão (`greatest(max(updated_at))` pelos `*_sync_ix`, sem índice novo); (2) índice montado fora da requisição; (3) ranking e índice com o texto já normalizado. Se ele quiser a busca no banco (pg_trgm em `catalogo.produto_busca`), eu crio a 0062, mas não recomendo para a v1.0.4.
