# D-1 (🔴): vendedor nunca alcança a exceção da RN-VEN-31 — consulta cancelamento_erp@1 com licença do usuário

## Contexto
rotaCancelarPedido (modules/vendedor/api/pedidos.ts) chama tx.consultar(CONSULTA_CANCELAMENTO_ERP, {}) com a licença padrão 'usuario' (apps/api/src/outbox.ts transacaoTenant). O módulo integracao só está nos perfis admin e analista (modules/integracao/manifest.ts perfis), então para vendedor, supervisor, gerente e assistente a consulta lança ConsultaIndisponivel, cai no catch e vira 422 RN-VEN-CANCELAR-APOS-ENVIO mesmo com o Conector aceitando. { licenca: 'tenant' } não vale em POST (ADR 0025). Passos: ligar aceita_cancelamento no Conector de A, vendedor-1 POST /v1/vendedor/pedidos/<integrado>/cancelar → 422 (esperado 200 cancelamento_solicitado). Caso E2-V em tests/integracao/api/cancelamento-erp-t0114.test.ts (CI).

## O que preciso / o que mudou
Corrigir para que o perfil que cancela (vendedor e supervisão) veja o aceite do tenant: por ex. o engenheiro-software liberar licenca 'tenant' para essa consulta em escrita (ADR) ou outra via que o engenheiro aprovar. Se precisar de ADR, alinhe com o engenheiro-software.

## Pronto quando
Pronto quando o E2-V do arquivo acima passar no CI sem mudar os outros casos (o E2-BKO com o analista já cobre a cadeia do Hub).
