# Consulta vendedor.pedidos_da_meta@1 (pedidos e faturamentos para o realizado das metas)

Contexto | T-0065 B (RN-CORE-21): o Core liga domain/apuracao.ts ao realizado da tela Metas e de /v1/core/indicadores. Meta de pedido = aprovados (aprovado, integrado, faturado) pela data de emissão; meta de faturamento = data do faturamento do ERP, líquido de cancelamento e devolução. O Core não lê vendedor.* e hoje só tem o read-model indicador_diario. Não existe consulta pública do Vendedor com pedidos. | Preciso de `vendedor.pedidos_da_meta@1` (ofereceConsultas no manifest do Vendedor, contrato em modules/vendedor/contracts). Entrada: { usuario_ids: uuid[] (máx 500), periodo: 'AAAA-MM' }; traga uma folga de 1 dia UTC em cada borda do mês (o Core decide o mês civil pelo fuso do tenant). Saída: { pedidos: [{ vendedor_id, criado_por?: uuid|null, cliente_id?: uuid|null, emitido_em: ISO UTC (data do pedido), aprovado_em?: ISO|null, status: string (valor do ORDER_STATUSES do contrato), total_cents: int, frete_cents?: int|null, cancelado_cents?: int|null }], faturamentos: [{ vendedor_id, cliente_id?, faturado_em: ISO UTC (data do faturamento informada pelo ERP), valor_cents: int, cancelado_cents?, devolvido_cents? }] }. vendedor_id é o dono do número (pedido do gestor em nome do vendedor vem com o vendedor). Só tenant atual, só pedidos não removidos; orçamento fora; frete separado em frete_cents. Escopo de carteira é do Core (ele só pergunta pelos usuários visíveis). Quando publicar, avise: eu adiciono usaConsultas e opcional/depende no manifest do Core e troco a porta FontePedidosDaMeta (modules/core/api/metas.ts) pela consulta, sem mudar domínio nem telas. | Pronto quando: contrato com teste publicado em modules/vendedor/contracts e consulta implementada na API do Vendedor; recado de volta com o nome final.
