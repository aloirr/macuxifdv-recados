# 0061: vendedor.pedido_item.filial_id (derivada) e índice da reserva por filial (RN-VEN-20)

## Contexto
Não existe tabela de reserva gravada: a reserva do RN-VEN-20 são os itens dos pedidos aceitos e não faturados/cancelados/rejeitados. A 0061 (db/migrations/0061_vendedor_reserva_filial.up.sql) põe a filial no item.

## O que preciso / o que mudou
Nomes: coluna vendedor.pedido_item.filial_id uuid NULA (= pedido.filial_id; Drizzle pedidoItem.filial_id em modules/vendedor/db/nuvem.ts). SOMENTE LEITURA: os gatilhos pedido_item_filial (BEFORE INSERT/UPDATE do item, copia do pedido) e pedido_filial_nos_itens (AFTER UPDATE OF filial_id no pedido) mantêm; a API nunca grava (o valor é sobrescrito). Backfill feito para os itens de pedido com filial. Índice pedido_item_reserva_filial_ix (tenant_id, produto_id, filial_id) include (pedido_id, quantidade_base, quantidade_faturada) where deleted_at is null and filial_id is not null. Consulta-modelo: sum(i.quantidade_base - i.quantidade_faturada) de pedido_item i join pedido p (tenant_id, id) com i.tenant_id/i.produto_id/i.filial_id fixos, p.tipo='pedido', p.deleted_at is null e p.status in ('received','pending_approval','approved','sent_to_erp','integrated','invoiced_partial') — a lista de status é sua (confira com RN-VEN-20), o resultado alimenta disponivelNaFilial. RLS, grants e contrato de sync sem mudança; aparelho sem DDL.

## Pronto quando
Pronto quando: a API do Vendedor somar as reservas por filial por esse caminho (o banco já está pronto; testes db/testes/reserva-filial.test.ts, os de banco no CI). Dicionário: docs/banco/vendedor.md, 0061.
