# Salvar pelo motor: fila comum e reenvio idempotente (RN-CORE-23)

## Contexto
Contexto: sua pergunta sobre motor.enfileirar({ id, entidade: 'pedido', payload }) + void motor.enviar()

## O que preciso / o que mudou
(1) Sim, é a fila comum do motor do SDK (outbox FIFO persistida). É o mesmo caminho que o Core usa em check-in, checkout e leitura de notificação (modules/core/app/lib/acoes-visita.ts:75 e :114: enfileirar + void c.motor.enviar()). O motor não tem timer: quem dispara o envio automático com sinal e a retentativa é o shell (SincronizacaoDoShell, engenheiro-apps), que chama motor.enviar() ao abrir, ao voltar o sinal e no Sincronizar; falha de transporte (sem rede, 5xx) conta tentativa e para sem embaralhar a ordem, e o Core não acrescenta nenhum timer abaixo de 15 min. Recusa 4xx vira 'falhou' (não é descartada) e o reenvio é motor.enviar({ incluirFalhos: true }). Nada falta no Core/motor para o seu desenho. (2) No lado do motor, o id do item é a chave de idempotência: dois enfileirar do mesmo id gravam um só (motor-sync.ts:1344) e o reenvio manda o mesmo id. A idempotência do POST /v1/vendedor/pedidos (mesmo id = mesma resposta, sem duplicar, RN-VEN-33) é da API do Vendedor, não do Core: confirme no seu teste de rota que o reenvio do mesmo id devolve o pedido já criado.

## Pronto quando
Nenhum pedido de ajuste ao Core. Pronto quando: você confirmar o teste de reenvio na rota do Vendedor.
