# D-MP2 corrigido na 0046: MP-06d portal pode virar it quando o CI reprovar o it.fails

## Contexto
D-MP2 corrigido no banco pela migração nova db/migrations/0046_plataforma_portal_multiperfil.{up,down}.sql (só funções, em cima da 0045). Não coube na 0040: o filtro lê plataforma.usuario_perfil, perfil e perfil_permissao, que nascem na 0041.

## O que mudou
- plataforma.usuario_entra_no_portal(p_tenant uuid, p_usuario uuid) -> boolean: gêmea de podeEntrar(perfis, 'portal') do SDK sobre os perfis vivos e ativos do usuário (ao menos um, TODOS de base admin, acesso.portal pela união: sobreposição viva, senão a fábrica). SECURITY INVOKER, sem EXECUTE para app, worker, portal ou PUBLIC.
- sa_contas_para_login, sa_abrir_sessao_portal, sa_escolher_empresa e sa_sessao_valida: o texto da 0040 + o filtro (mesmas assinaturas, retornos e ACLs; continuam 14 sa_* do portal). Admin + qualquer outra base (vendedor, promotor, supervisor, gerente, analista, assistente) = 0 linhas no login (sem oráculo), sem sessão, e a sessão viva cai na hora se a conta da empresa atual ganhar um perfil de outra base.
- Testes: db/testes/portal-multiperfil.test.ts (estático verde local; banco só no CI): admin só entra; admin + cada outra base = podeEntrar do SDK (não entra); dois perfis admin e acesso.portal revogado (sozinho fecha, com o de fábrica não); sessão que cai; a mesma pessoa em A (só admin) e B (admin + promotor) entra só em A; up/down.

## O que preciso
Quando o CI rodar com a 0046, o it.fails '[D-MP2 aberto] MP-06d admin + vendedor ... portal' de tests/integracao/api/multiperfil-api-t0094.test.ts deve reprovar: troque por it e tire o D-MP2 do cabeçalho. Matriz docs/testes/T-0111.md §4: admin + analista também não entra (RN-CORE-35, ADR 0033 §7: um perfil que não seja admin fecha o portal).

## Pronto quando
MP-06d portal como it verde no CI.
