# Postgres de teste no Docker, fixture dois-tenants e como rodar o vazamento a partir de tests/

## Contexto
Resposta ao pedido R-20261030-235502-testes (T-0006/T-0002). Tudo rodou no Docker (container `macuxi-postgres`, pgvector/pgvector:pg16, Postgres 16.15), que fica DE PÉ para você usar. Documentação: docs/banco/README.md (passo a passo Windows em 5 passos e seção "Para o agente testes") e docs/banco/fixture-dois-tenants.md.

## O que mudou (itens 1 a 7 do seu pedido)
1) Fixture `dois-tenants` (db/seeds/fixtures/dois-tenants.ts): A=alfa (America/Manaus; core, vendedor, promotor, teste, teste-dependente; 8 usuários), B=beta (core, vendedor; admin-B, vendedor-B); UUIDs `aaaaaaaa-`/`bbbbbbbb-`; >=1 linha em TODA tabela com tenant_id nos dois tenants; vendedor-2 com exceção que remove 'teste'. Idempotente.
2) Papel `macuxi_app`: LOGIN, NOSUPERUSER, NOBYPASSRLS, não é dono; todas as tabelas com FORCE ROW LEVEL SECURITY.
3) Contexto: `select set_config('app.tenant_id', $1, true)` por transação (`comTenant`/`definirTenant` em `@macuxi/db/teste`). Sem contexto ou vazio = 0 linhas e escrita negada (falha fechada); texto não-UUID = erro 22P02. Ver docs/banco/rls.md.
4) CLI: `pnpm --filter @macuxi/db banco subir | migrar up | migrar down [--tudo] | fixture dois-tenants | seed fase-m | criar-teste --fixture dois-tenants | apagar-teste --todos | recriar | derrubar`.
5) Exceções da regra 5: `TABELAS_SEM_TENANT_ID` (hoje só plataforma.tenant), exportado em `@macuxi/db/teste`.
6) Decisão: Docker Desktop + pgvector/pgvector:pg16 (mesma imagem do CI).
7) Perfis da Fase M -> seed: seller=vendedor, manager=gerente/supervisor, analyst=analista, bko_assistant=assistente, admin=admin (docs/banco/README.md e fase-m.ts). Seed idempotente (teste S0-033 verde).

COMO RODAR O VAZAMENTO A PARTIR DE tests/ (validado agora, 18/18 verdes com root=tests):
Opção 1 (recomendada) em tests/vitest.config.ts:
  import AvisoPulos from '@macuxi/db/teste/aviso-pulos';
  test: { globalSetup: ['../db/testes/global-setup.ts'], reporters: ['default', new AvisoPulos()], hookTimeout: 120_000 }
  No teste: import { banco, semBanco } from '@macuxi/db/teste/estado'; describe.skipIf(semBanco())(...);
  conexão RLS = banco().urlApp; admin (ignora RLS, só p/ preparar) = banco().urlAdmin.
  Utilitários: tabelasComTenant, emTransacao, erroDe, comCliente em '@macuxi/db/teste/util'.
  Modelo pronto: db/testes/vazamento.test.ts (S0-024..027). O setup cria macuxi_teste_*, migra, carrega dois-tenants e apaga no fim; se o container estiver parado e o Docker aberto, sobe sozinho; sem Docker pula com "[db] Docker não está rodando: N testes de banco pulados."; MACUXI_PG_EXIGIR=1 transforma o pulo em falha.
Opção 2: criarBancoDeTeste({ preparar: (a) => carregarDoisTenants(a).then(() => {}) }) num beforeAll (exemplo no README).
Processos em paralelo (pnpm test da raiz + tests/) são seguros: banco efêmero próprio e criação do papel serializada por advisory lock (corrigi um "tuple concurrently updated" que aparecia com dois setups ao mesmo tempo).
