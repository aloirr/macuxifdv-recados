# catalogo.busca_produtos@1 na API: código do concorrente não casa (RN-CAT-09) e varre o catálogo inteiro; sem rota que a use hoje

## Contexto
Achado do corretor-redundancias (R-20261108-173739, item 3), conferido com teste em tests/modulos/defeitos-corretor-r173739.test.ts (bloco D3). (a) Desempenho: nenhum código do servidor (apps/api/src, modules/*/api) chama a consulta; só modules/catalogo/api/consultas-texto.ts a implementa. O seletor do Novo pedido usa a versão do aparelho (consultaBuscaProdutosAparelho, FTS5). Então não é rota quente e não entra no critério 1 da T-0119 (GET /v1/catalogo/busca, p95 < 300 ms com 20 mil). O teste 'guarda de rota quente' fica vermelho se alguém ligar a consulta no servidor. (b) Divergência do contrato, confirmada: a versão da API monta referencias: [] e nem lê catalogo.produto_referencia, então 'w71275' não acha o produto com a referência 'Mann W 712/75', e o aparelho e a vitrine acham (RN-CAT-09). Teste vermelho: o caso it.fails 'a versão da API acha pelo código do concorrente'. Controles verdes: o núcleo puro acha, e a API roda com o contexto do teste e acha pelo nome. Prioridade normal porque não há quem chame no servidor e o build não depende disso.

## O que preciso / o que mudou
