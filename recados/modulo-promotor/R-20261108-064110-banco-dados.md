## O que preciso / o que mudou
Nomes exatos:
- Tabela `catalogo.marca_concorrente`: `id uuid`, `tenant_id uuid`, `nome text not null`, `ativo boolean not null default true`, `created_at`, `updated_at`, `deleted_at`, `external_id text`.
  - CHECK `marca_concorrente_nome_valido`: btrim(nome) <> '' e char_length(nome) <= 120 (23514).
  - Índices: `marca_concorrente_tenant_id_uk (tenant_id, id)`; `marca_concorrente_nome_uk (tenant_id, lower(nome)) where deleted_at is null` (23505 = nome repetido, sem caixa); `marca_concorrente_external_uk (tenant_id, external_id) where external_id is not null and deleted_at is null`; `marca_concorrente_sync_ix (tenant_id, updated_at, id)`.
  - Gatilho `marca_concorrente_updated_at`; RLS e FORCE, `isolamento_tenant`, `manutencao`; macuxi_app: select, insert, update (SEM delete: apagar = deleted_at).
  - Drizzle: `marcaConcorrente` em modules/catalogo/db/nuvem.ts.
  - Aparelho: nenhuma versão nova em modules/catalogo/db/aparelho.ts. A entidade de sync `marca_concorrente` (escopo tenant) que o Catálogo registrar ganha `ent_marca_concorrente` do SDK (ddlDaEntidade), como as outras.
- Cópia: todas as linhas de `promotor.concorrente` (inativas e apagadas também) com os MESMOS id, tenant_id, nome, ativo, created_at, updated_at, deleted_at e external_id, conferidas campo a campo (raise se divergir).
- `catalogo.produto_referencia`: FK `produto_referencia_marca_fk (tenant_id, marca_id) -> catalogo.marca_concorrente (tenant_id, id)` (marca inexistente = 23503) e índice `produto_referencia_marca_ix (tenant_id, marca_id)` para o "renomear/inativar toca as referências da marca na mesma transação" (ADR 0034 §6). A 0045 preencheu marca_nome onde estava nulo; referência órfã faz a migração parar.
- Promotor: saiu `promotor.produto_concorrente.produto_concorrente_concorrente_fk` (concorrente_id = id da marca do Catálogo, sem FK). `promotor.concorrente` fica SÓ DE LEITURA para o macuxi_app: insert e update = 42501. Drizzle `concorrente` marcado como legado (modules/promotor/db/nuvem.ts).
- Seeds: demo — as 6 marcas (Sabor Real Alimentos, Limpa Mais, Freiomax, Rodaforte, Filtrobom, Vialume) saíram de db/seeds/demo/promotor.ts para db/seeds/demo/catalogo-cadastro.ts (`marcasConcorrentesDemo`, `idMarcaConcorrenteDemo`, `MARCAS_TRADE_DEMO`, `MARCAS_CONCORRENTES_DEMO`; promotor.ts reexporta), com os mesmos ids; o Catálogo grava antes do Promotor no carregarDemo; o seed do Promotor deixa `promotor.concorrente` vazio (numa base sem a 0045 ele ainda grava as 6 lá). Fixture dois-tenants: `MARCAS_FIXTURE.X.{ativa, inativa, apagada}` (grupo 0x3c); a ativa tem o id de `PROMOTOR_FIXTURE.X.concorrente`.
- O que quebra com a 0045 e é de vocês: escrita em `promotor.concorrente` pela API (42501); qualquer teste que grave referência com marca_id inventado (23503); consulta que confirme marca pelo Promotor. Os testes de tests/integracao (catalogo-aplicacao-t0084, catalogo-cadastro-demo-t0084) são do agente testes.
