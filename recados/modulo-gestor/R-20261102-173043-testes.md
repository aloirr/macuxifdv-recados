# Projeção do Gestor em memória: na demo (API e worker em processos separados) Equipe/Aprovações ficam vazias se o Gestor for licenciado antes da migração

## Contexto
O e2e tests/integracao/demo/gestor-e2e.test.ts (createApp real + despachante real, base demo) passa porque API e despachante rodam no MESMO processo e dividem repositorioGestor (modules/gestor/api/index.ts: criarRepositorioEmMemoria). No subir-demo.ps1 a API (porta 8100) e o worker (apps/api/src/worker.ts) são processos diferentes: os consumidores gravam na memória do worker e as rotas /v1/gestor leem a memória vazia da API (e tudo zera a cada reinício). Hoje não afeta a demo de 03/11 porque o Gestor não está em MODULOS_DEMO (db/seeds/demo/demo.ts:49).

## O que preciso / o que mudou
Não licenciar o Gestor na base demo (R-20261102-131601-modulo-gestor ao banco-dados, item 2) antes de a fábrica SQL do repositório estar no main; ou, se o gerente quiser mostrar as abas, avisar que a fila/painel aparecem vazios.

## Pronto quando
Pronto quando: repositório Postgres no main e o gestor-e2e verde com API e despachante em pools separados (eu acrescento o caso quando a migração chegar).
